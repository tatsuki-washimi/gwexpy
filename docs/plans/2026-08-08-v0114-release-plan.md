### PR-2: #633 — timezone 再解釈の禁止（+ WIN 警告 + 時刻分類の機械化）

### PR-6: #646 + #650 + #651 — time モジュールの時刻契約修正

**実装**:
1. **#646**: `gwexpy/time/core.py:138` の `np.datetime64 → .item()` 経路を廃止し、Astropy `Time` 経由で直接 GPS 化（`datetime64[us]` へ cast してから `.item()` する workaround は sub-µs 喪失のため不採用）。テストは2系統に分離する — (a) 各 resolution（s/ms/us/ns）の値が「その dtype が量子化後に表現する instant」の正しい GPS へ変換されること（resolution ごとに独立した reference。同一文字列を各 dtype に変換すると instant 自体が量子化で異なるため、単純な 4 分解能一致は要求しない）、(b) 全 resolution で表現可能な instant（整数秒など）では 4 分解能の結果が完全一致すること + scalar/vector parity。**correctness oracle は float GPS に置かない** — `LIGOTimeGPS` の整数 ns / Astropy `Time` の高精度表現（jd1+jd2）/ seconds+nanoseconds の exact pair を oracle とし、public float へ落とした最終値のみ ULP-aware tolerance（GPS ~1.4e9 s の float64 ULP ≈ 2.4e-7 s 基準）で比較する（旧案の `abs=1e-8` は float64 GPS の ULP より小さく成立しないため不採用）。
2. **#650**: `from_gps()`（`gwexpy/time/core.py:169`）の vector / Astropy 経路を scalar 経路と同じ **UTC-aware datetime** に統一。naive を期待する既存テストを更新。host timezone 非依存をテストで保証（naive→aware は observable change として CHANGELOG に before/after 記載）。
3. **#651**: naive local datetime への `replace(tzinfo=)` 単純付与（`gwexpy/io/utils.py:74,94` の `ensure_datetime` 経路）を fold/gap 検出付きに変更: `zoneinfo` で ambiguous（fold=0/1 で UTC が異なる）/ nonexistent（round-trip 不一致）を検出し `ValueError`。新 public API（`fold=`/`ambiguous=`/`nonexistent=`）は追加しない（disambiguation policy は v0.2.0）。UTC / Asia/Tokyo / fixed offset の regression なしを明示テスト。
4. **Leap-second 回帰（推奨・仕様変更なし）**: `from_gps()` の UTC-aware 化が leap second 近傍で現行 GWpy/Astropy contract を意図せず変更しないことを固定する — leap second 直前・直後の GPS 値（例: 2016-12-31 → 2017-01-01 境界）の現行挙動を regression test 化し、leap-second instant 自体（Python `datetime` は `23:59:60` を表現不可）が現行 API でどう扱われるかも記録する。新しい仕様は要求しない。
5. テスト: `tests/time/test_time_core.py` / `tests/time/test_time_contracts.py` へ回帰追加（+ #651 は `tests/io/` の timezone 経由テストにも波及確認）。

**検証**: `conda run -n gwexpy pytest tests/time tests/io -q` green。physics-reviewer 必須（時刻セマンティクスの behavior-visible 変更。#650 は Issue の指示どおり P0 群より慎重にレビュー）。
