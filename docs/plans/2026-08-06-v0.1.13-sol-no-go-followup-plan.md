# GWexpy v0.1.13 Sol NO-GO フォローアップ計画

> **実行モデル:** 実装とローカル試験は GPT-5.6-Luna、各レーンの独立レビューは GPT-5.6-Terra、凍結した同一 SHA の最終統合監査だけ GPT-5.6-Sol を使用する。Luna を起動できない場合は代替せず停止する。

## 1. Goal / Non-goals

**Goal:** Sol の最終統合レビューで検出された2件の HIGH と公開文書の不整合を解消し、`main` と `maint/0.1` が一致する凍結 SHA `R` に、required CI、4-cell smoke、配布物 hash、Terra の advisory review、90日保持の統合証跡を結び付ける。その後、同じ `R` だけを対象に Sol の統合監査を再実行する。

対象は次の3点に限定する。

1. PyPI へ渡す wheel/sdist と sidecar を物理的に分離し、余分なファイルを fail-closed で拒否する。
2. 同一 `publish-release.yml` run 内で Python 3.11/3.12 × wheel/sdist の4結果を集約し、候補ツリー外の統合 evidence artifact を作る。
3. 英日公開文書の古い release、CLI、citation の主張を版中立かつ正式 metadata と整合する表現へ直す。

**Non-goals:** 公開 API、TimeSeries/Field/Histogram/List/I/O 契約、物理計算、v0.2.0 延期項目、parallel/streaming、FFL 実装、Histogram arithmetic は変更しない。tag、PyPI、GitHub Release、Zenodo の公開はこの計画の自動実行範囲外である。

## 6. Technical Contracts

### 6.1 Publish payload

- build は新しい空ディレクトリから、正規化された名前の wheel 1件と sdist 1件だけを `release-payload-<R>` に入れる。
- `LICENSE.sha256`、distribution hash manifest、smoke JSON、review evidence は payload と別 artifact にする。
- payload validator は欠落、重複、余分なfile、symlink、非regular file、path traversal、名前／version不一致、hash不一致を拒否する。
- smoke と publish は hash manifest が指定する正確なfile名を使い、`find ... -print -quit` で最初の1件を選ばない。
- PyPI action の `packages-dir` は payloadだけをdownloadした新しい空ディレクトリを指す。publish jobはsidecar artifactをdownloadしない。
- candidate dispatch と tag push の concurrency group は同じ `expected_tag` に正規化し、同一releaseのdry runとpublishを並走させない。
- actionはfull SHA pinを維持し、default permissionは`contents: read`、`id-token: write`はpublish jobだけに与える。

### 6.2 Release build toolchain

- `requirements/release-build.txt` は Ubuntu/Python 3.11 用の pip/build/twine/setuptools/wheel と必要なtransitive dependencyをexact versionかつhash付きで固定する。
- workflowは`--require-hashes`で導入し、`python -m build --no-isolation`を使う。浮動の`pip install --upgrade pip build twine`は禁止する。
- lockの生成方法、対象platform、検証方法を`RELEASING.md`に記録する。lock変更はartifactと全reviewを無効化する。

### 6.3 Four-cell smoke and evidence

- 各cellは固定名 `python-{3.11|3.12}-{wheel|sdist}.json` を一件だけ出力する。
- schemaは未知keyを許さず、少なくとも`source_sha`、Python version、distribution kind/file/hash、repository/embedded LICENSE hash、installed version、import、`register_all()`、smoke statusを型付きで持つ。free-text logやURLは持たせない。
- evidence jobは同じ`publish-release.yml` runの`verify`、`build`、`smoke`に依存し、cross-run artifact選択をしない。repository ID、run ID、workflow SHA/ref、source SHA、expected tag/versionをmanifestへ結ぶ。
- collectorは4つのmatrix keyが厳密に一件ずつあること、payload/sidecar/smoke間のhash・version・SHAが一致することを検証する。余分なfile、unknown key、missing/duplicate cell、symlink、非regular file、失敗／skipを拒否する。
- 最終 artifact 名は `v0113-integration-evidence-<40-character-source-sha>`、内容はallowlistされたaggregate JSONだけ、`retention-days: 90` とする。raw review、prompt、command log、username/email、header、Cookie、Authorization、signed/credential URLは入れない。
- Terra情報は自動化されたadvisory reviewの記録であり、本人認証、法的承認、公開authorizationとは扱わない。公開authorizationは人間とprotected environmentに残す。

### 6.4 Non-circular Terra binding (`S` → `R`)

- Terraは統合内容commit `S` のLane A/B path scopeをレビューする。
- schema versionは`gwexpy-v0113-review-evidence-v1`。各entryはlane、role、model/effort（orchestration metadata）、`reviewed_commit=S`、scope path、scope digest、verdict、UTC timestamp、raw report SHA-256、sanitized finding IDだけを持つ。raw reportは収録しない。
- canonical scope digestは、対象pathをUTF-8 byte順にsortし、`git ls-tree -r -z --full-tree S -- <paths>`が返す `mode SP type SP object-id TAB path NUL` のbyte列をSHA-256へ入力する。missing/duplicate/out-of-scope pathは失敗とする。
- CoordinatorはTerra完了後、正本の完了checkboxとactual attestation manifestだけを更新する。`git diff --name-only -z S..R`で許すpathは次の2件だけである。

  - `docs/plans/2026-08-06-v0.1.13-sol-no-go-followup-plan.md`
  - `docs/developers/plans/manifests/audit-manifest-v0.1.13-sol-followup.yaml`

- plan差分は既存checkboxの`[ ]`から`[x]`への遷移だけを許し、残りの行はbyte-identicalとする。manifestはschema、digest、APPROVED、required lane、重複、unknown keyをfail-closedで検証する。
- `R`がPR merge commitでも、上記2件以外のtree差分があればTerra reviewを無効にして新しい`S`からやり直す。最終の2 audit recordsはSolが`R`上で監査する。

### 6.5 Frozen branches

- `scripts/validate_release.py`にreview-evidence検証と別のfrozen-tip modeを設ける。
- main統合直後、maint更新前はS→R validatorだけを実行する。frozen-tip validatorはまだ成功条件にしない。
- 人間が`maint/0.1`をfast-forwardした後、frozen-tip modeはfetchした`origin/main`と`origin/maint/0.1`がともに`source_sha=R`であることを要求する。maint fetchの欠落／失敗を`|| true`で無視しない。
- candidate dry runとtag publishはfrozen-tip modeを必須にする。どちらかのbranchが動いた場合、tag runを含めてfail-closedにする。

### 6.6 Public docs

- install pageは「PyPIで公開済み。利用可能な版はPyPI/release pageで確認」とし、公開前にv0.1.13をcurrentと断定しない。
- CLI例は`<installed version>`または明示的な例示とし、0.1.0/0.1.10を現行出力として残さない。
- citationは`<version used>`、正式タイトル、exact tagの`CITATION.cff`を使う手順を示し、mutableな`main`を再現可能な引用元と表現しない。
- redesigned source、JA PO、legacy EN/JAを閉じたinventoryとして検査する。`pyproject.toml`の真実はPython `>=3.11`であり、「3.11/3.12だけが宣言版」と誤記しない。
- `CITATION.cff`、`.zenodo.json`、CHANGELOGのversion/date/title/license/creator/identifierをread-only照合する。相違や日付繰越があればBの小修正として処理せずrelease cycleを再凍結する。
- version DOIとconcept DOIは公開後のPOST-DOI PRでtag外に記録し、公開済みtag/artifact/Zenodo version recordを遡及変更しない。

## 9. External Readback / Publication Checks

- GitHub artifact readbackはartifact ID、name、API digest、`created_at`、`expires_at`をUTC (`YYYY-MM-DDTHH:MM:SSZ`)で記録する。`retention-days: 90`の受理条件は`expires_at - created_at >= 90 days - 5 minutes`とし、repo/org policyが90日未満へcapしていないことを確認する。readback時点から90日残るとは主張しない。run/artifact削除や期限切れで証拠は無効になる。
- PyPI公開後は公式v0.1.13 release-file metadataをfilename集合の正本として読み、tag-run payloadのwheel 1件＋sdist 1件と完全一致させる。PyPI宣言SHA-256と実download byte SHA-256を両方比較し、extra、missing、substitutionを拒否する。
- manual dry runはpayload生成、4-cell smoke、evidence集約を検証するが、実PyPI upload、OIDC、environment approvalを実行しない。これらは人間readbackとtag runの制御対象である。
- external API endpointとtimestamp/hash fieldは実行時の公式GitHub/PyPI documentationに基づいてRELEASING evidenceへ記録する。token、credential URL、raw API responseは保存しない。

## 10. Invalidation / NO-GO

次のいずれかで、該当範囲から検証をやり直す。

- `R`、S→R許可path、workflow、action pin、release lock、docs、metadata、release date、artifact hash、Terra scope/verdictが変わる。
- S→R差分がcoordinator-only 2ファイル以外を含む、またはplan差分がcheckbox遷移以外を含む。
- `origin/main != origin/maint/0.1 != R`、maint fetch失敗、tag peel不一致、branch tip移動がある。
- required CI/docs/full gate不合格、dedicated gateのskip/error/failure、4-cellの欠落／重複／skip／failureがある。
- payloadにwheel/sdist以外が入る、file/hash/license/version/source SHAが一致しない。
- evidence schema不正、90日policy/readback不合格、artifact/run削除、secret/PII/free-text URL混入がある。
- ruleset、PyPI Trusted Publisher、environment、Zenodo、milestoneのreadbackが未完または不合格である。
- Lunaを使用できない、TerraがHIGH以上を残す、Solが`NO-GO`、人間最終GOがない。

## 11. Reviewer Status / Residual Risks

`mplan` review sequence:

- Drafter: GPT-5.6-Terra / high
- Critic: GPT-5.6-Terra / high
- Guardian: GPT-5.6-Terra / high
- Lawyer/Audience: GPT-5.6-Terra / high
