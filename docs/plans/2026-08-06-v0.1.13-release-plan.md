# GWexpy v0.1.13 技術的 NO-GO 解消計画

> **実装ワーカー向け:** 実装とローカル試験は GPT-5.6-Luna、レーンレビューは GPT-5.6-Terra、統合監査だけ GPT-5.6-Sol を使用する。Lunaを起動できない場合は代替せず停止する。

## 1. Goal / Assumptions / Critical Path

**Goal:** 全技術的 NO-GO を同一のリリースSHA上で解消し、人間に残す作業をcredential・公開設定の確認、最終GO、不可逆な公開操作だけに限定する。

**Architecture:** 現候補を直接rebaseせず保存し、PR #631取り込み後の`origin/main`から新しいRC worktreeを構築する。機能実装はI/OとROOTだけを並列化し、CI、全体品質、公開物は直列化する。

**前提:**

- dirtyな`/home/washimi/work/gwexpy`は変更しない。
- 現候補`/tmp/gwexpy-v0113-release`、HEAD `20188b6f2b637b953f76345dd0f5f26179513181`は証拠として保存する。
- PR #631のheadが`3c803eab40c314b43682f75410f1e974f3200c90`から変化していたら停止して再レビューする。
- full Ruff formatで現状349ファイルが対象になるが、承認済みfull gateを弱めず、機械的な独立commitとして全件整形する。
- cropの非グリッド境界はGWpy floor互換とする。exact grid境界は整数位置へsnapし、どちらもデータ範囲へclampする。
- 公開済みのField/List契約や他の承認済みAPI契約は変更しない。
- #508、#513、#618、#620、PR #625などの延期対象を混入させない。

## 2. Public Contracts And Work Lanes

### 公開契約の追加明確化

- `crop(start, end)`は、exact sample境界なら位置slice`[i:j]`と一致させる。
- off-grid境界は`floor((bound-x0)/dt)`を両端へ適用し、負index wrapを防ぐため`[0, len]`へclampする。
- `xindex`生成前後、TimeSeries/TimeSeriesMatrix、bounded NetCDF/Zarr readで同一結果にする。
- NetCDF v2の`sample`座標は`int64`かつ厳密な`0..N-1`のみ受理する。
- ROOTから生成される最終`Histogram.values`までC/S/I/L/F/Dのnative dtypeを保持する。`sumw2`は常にfloat64。

## 4. Verification Gates

```bash
rtk conda run -n gwexpy python scripts/ci/run_gate.py io-gwf
rtk conda run -n gwexpy python scripts/ci/run_gate.py io-netcdf
rtk conda run -n gwexpy python scripts/ci/run_gate.py interop-root
rtk conda run -n gwexpy ruff check gwexpy tests
rtk conda run -n gwexpy ruff format --check gwexpy tests
rtk conda run -n gwexpy mypy gwexpy --ignore-missing-imports
rtk conda run -n gwexpy pytest tests -q
rtk conda run -n gwexpy python scripts/check_release_metadata.py
rtk conda run -n gwexpy python -m build --sdist --wheel --no-isolation
rtk conda run -n gwexpy python scripts/check_release_artifacts.py dist
rtk conda run -n gwexpy twine check --strict dist/*
```

full pytestは中断・timeoutなしで完走する。dedicated gateは`tests > 0`かつ`skipped=errors=failures=0`。legacy docsとdocs_redesign EN/JAはdisposable sourceからfresh buildする。GitHub上の最終証拠はmain/maint共通SHAを指す。wheel/sdist双方にrepository LICENSEとhash一致するLICENSE一件を含め、Python 3.11/3.12 × wheel/sdistの4セルを成功させる。

## 5. Reviewer Status / Residual Risks

`mplan`のDrafter、Critic、Scientist、Guardian/Lawyer、Consistency reviewerによるレビューは**approved with minor risks**。残るminor riskは、(1) external evidence artifactの名前・90日retention・SHA一致をworkflow testで検証すること、(2) POST-DOI PRがtag外の監査記録で公開済みartifactを遡及変更しないことをPR本文とmanifestに明記することだけである。

Lunaが利用不能、ROOT実機gateがskip、full gate不合格、main/maint SHA不一致、credential再検証未完、またはSolがNO-GOなら公開へ進まない。
