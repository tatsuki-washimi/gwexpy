# API 安定性ポリシー

[English version](api-stability-policy.md)

このポリシーは、GWexpy の公開 API に付ける安定性ラベルを定義する。
ラベルの意味を定める文書であり、GWexpy 全体を stable とみなしたり、すべての API を分類したりするものではない。

## 適用範囲とラベル

ラベルは、必要な最小の単位であるモジュール、シンボル、振る舞いのいずれかに付ける。
ラベルを追加、変更、削除したときは、該当する API 文書とリリースノートに記録する。

| ラベル | 定義と保証 |
|---|---|
| **stable** | 公開 API。明文化した非推奨通知と期間なしに破壊的変更を行わない。ただし、正しさまたはセキュリティ上の緊急事態は、例外として明示的に文書化できる。 |
| **provisional** | 提供済みで、利用に十分なサポートがある。ただし、非推奨サイクルなしにパッチまたはマイナーリリースで変更できる。変更にはリリースノートと移行情報による開示が必要である。 |
| **experimental** | 明示的なオプトインによる研究用の対象。いつでも変更または削除できる。互換性の保証はない。 |

ラベルのないレガシー API は、新しい保証を含意しない。
既存の振る舞いから stable、provisional、experimental のいずれかを推測してはならない。

## リリース結果

deferred はリリースの結果であり、安定性の分類ではない。API 安定性ラベルでもない。
そのリリースで作業を出荷しなかったことを記録するもので、API を分類するものではない。
deferred は、現在のリリースより後へ作業を延期するようなリリース上の判断に使う。
第四の互換性保証や API 安定性ラベルの代用として使ってはならない。

## ラベルの変更

昇格では、契約とそれを裏付ける証拠を文書化してから、より強い保証を持つラベルへ移す。
降格では、理由を記録し、API 文書を更新し、移行への影響をリリースノートで開示する。

対応する契約監査が完了するまで、または記録した理由と証拠を添えて明示的に deferred とするまで、機能を stable に移してはならない。

provisional と experimental のラベルは、正しさ、セキュリティ、その他の適用可能な安全上の義務を免除しない。
ラベルが示すのは互換性への期待であり、障害や危険な状態を適切に扱う義務をなくすものではない。
