## Goal and boundaries

Add the internal I/O performance and scalability work under [#580](https://github.com/tatsuki-washimi/gwexpy/issues/580) to v0.2.5. Preserve public numerical results, dtype, metadata, warning/error behavior, and on-disk format unless an exception is explicitly listed below. Do not add a public API, dependency, or persistence schema. Exclude #587, #590, #519, and Numba. Include only the NumPy portion of #518 and the dtype-preserving portion of #586; track their remaining work separately.

W0 must revise `ROADMAP.md` so behavior-preserving internal performance and scalability corrections are patch-eligible when they add no public API, dependency, or persistence schema. An intentional observable divergence requires separate review, approval, and disclosure. Parser-level use of already accepted selectors is the patch-eligibility rationale for #589. Its **native-parser-only exception** permits warnings and decode errors arising exclusively from fully unselected DTTXML payloads to disappear. XML structural errors and selected-payload behavior must remain B1-equivalent. The external `dttxml` route retains its current behavior and is outside the #589 performance claim. This exception does not expand [#611 `non_intersecting_window_safety`](https://github.com/tatsuki-washimi/gwexpy/issues/611), which remains limited to completely disjoint plain HDF5 read windows.

B-F2 found a separate, reproducible SDB WAL concurrency difference. Old R
can validate units before a writer commit but fetch selected values after it;
the planned single read transaction returns values from the earlier snapshot.
For the deterministic B1 preflight `outTemp` 60→99 °F schedule, those
results are respectively 37.22222222222222 °C and 15.555555555555555 °C.
The proposed #585 exception covers SDB value, warning, and error differences
caused by a WAL writer committing after the reader pins its snapshot. Capture
selected/unselected payload, timestamp, `usUnits`, schema, and malformed-value
updates in a separate append-only B-F2-SDB baseline-v2 fault matrix **before
SDB runtime edits**. The B-F2-v1 CSV baseline stays immutable. Static-source
behavior remains B1-equivalent; no other lane inherits the exception. F2 cannot
become MERGE_READY without characterization, disclosure, and separate technical
review of the final exact concurrent scope. S2 qualification requires the
separate human scientific/data-model approval specified in the release plan.

The existing checkout has unrelated uncommitted changes. Execute each writer lane in an isolated worktree based on old R. C1 and C2 may be developed concurrently but must integrate in C1 → C2 order; F1–F5 integrate after C2; X follows F1–F5. Use the lane states `UNBASELINED → BASELINE_FROZEN → IMPLEMENTING → STRUCTURAL_GATE_GREEN → CORRECTNESS_GATE_GREEN → PERFORMANCE_EVIDENCE_GREEN → MERGE_READY`. **No runtime-code change is allowed before that lane reaches `BASELINE_FROZEN`.**

### B-F2: CSV cases and implementation

Freeze four benchmark routes before F2 runtime work:

| Route | Fixture and public call | Purpose and acceptance |
|---|---|---|
| ①a | Two-column, 4096-row CSV with a non-uniform frequency axis; `FrequencySeries.read(path, format="csv")` | [#394](https://github.com/tatsuki-washimi/gwexpy/pull/394) explicit-format fast path: wall primary non-regression, CPU supporting |
| ①b | **The same fixture**; `FrequencySeries.read(path)` for a `.csv` path | #394 auto-detect fast path: independent wall primary non-regression, CPU supporting |
| ② | Multi-channel TimeSeries CSV, read all channels | General parser overhead: wall and CPU co-primary improvement |
| ③ | Large multi-channel CSV, select one channel | Selection: only requested values materialized, lower peak RSS |

Record wall, CPU, peak RSS, validated token/column count, materialized column count, and Python-materialized value count. Do not combine ①a and ①b samples or gates. Both calls must return the same values, frequency axis, dtype, and unit. Keep the existing correctness regression for a **non-uniform frequency axis**: preserve column 1 exactly rather than reconstructing it from `(f0, df)`; do not copy a TimeSeries epoch onto the FrequencySeries.

For plain numeric, all-column CSV reads, remove whole-file `read_text`/`splitlines`/rejoin and Python cell-by-cell float conversion. Use bounded chunks with NumPy bulk conversion; cap each temporary parsed matrix chunk at 64 MiB, retain raw timestamp lexemes for the existing Decimal time validation, and preserve B1's row/line error contract. If one output row itself exceeds the cap, convert it in bounded column slices; the indispensable final row array may exceed 64 MiB. For channel/time selection or special header/config routes, stream with bounded buffers, validate **every field and timestamp in B1 row order**, and retain/convert only requested values. A selected-column bulk parser may be added only with an equivalent independent bounded all-column validator. Preserve timestamp semantics; #634 `time_scale` is out of scope. Stream CSV writer output instead of building a giant list/join; require byte identity under fixed encoding/newline on deterministic fixtures.

The writer benchmark targets the internal enhanced `write_timeseries_csv` helper
directly. Public `TimeSeries.write(format="csv")` uses GWpy's native writer and
is outside this writer performance claim. A zero full-size `write()` argument
count alone is insufficient: also prove that the candidate retains no
output-sized row list or joined string through an allocation probe or source
audit, and require the predeclared peak-RSS improvement and byte identity.

Run structural spies, uninstrumented timing, and sampled memory as separate runs. Use five samples per arm for baseline smoke and nine per arm for release evidence, interleaved `ABBA · BAAB · ABBA · BAAB · AB`. Cold timing includes fresh-process import/backend setup; warm timing starts after warm-up and times the function only. Structural work counters use predeclared exact bounds; baseline zero means already optimized **only** for those counters. For a positive lower-is-better noisy metric, set `improvement=(median_before−median_after)/median_before` and `noise=MAD_before/median_before + MAD_after/median_after`; require `improvement ≥ max(5%, 2×noise)` for a performance claim. Apply this separately to route ②'s wall and CPU, the CSV writer's peak RSS, and F3's native parser peak RSS; require route ③'s materialization bound and peak-RSS improvement. Routes ①a and ①b each use the small-input non-regression gate: `regression > max(10%, 3×noise)` confirmed in a second batch means HOLD. CI gates structure and correctness, not wall time.

For #588, canonical PSS evidence comes from Linux. Sample parent plus live workers simultaneously, using `max_t Σ PSS_process(t)` rather than a sum of individual peaks. Sample from before pool startup through worker exit at 10 ms; retry the **memory-profile run only** at 1 ms if a worker was not observed. Record PIDs/timestamps/counts and the limit of sampled peaks. Never silently substitute RSS for missing PSS.
