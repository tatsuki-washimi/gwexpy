## Review, evidence, and source transition

The final reviewed source `S` must contain the selected source scope and all
release-control work, including the workflow order that creates and verifies
the GitHub Release before the PyPI job can run. Three independent reviews—
`scientific-data-model`, `documentation`, and `release-security`—must approve
that exact `S` with matching scope digests. The scientific/data-model review
must assess both proposed exceptions and all twelve historical disposition
IDs. Exact-artifact observations belong to qualification on `R`; a probe exit
code alone is not a scenario pass.

The readiness file at `S` must be byte-for-byte equal to
`V025_EMPTY_REVIEW_EVIDENCE_PLACEHOLDER` in `scripts/validate_release.py`.
It is intentionally empty and grants no approval. The release owner must then
record fresh human approval bound to final `S`, its scope digest, the exact
disposition-document SHA-256, both scoped exceptions, and each disposition
ID and decision. The canonical v0.2.5 comment tokens and validator remain the
authority; historical comments cannot be rebound.

Only after all reviews and human approval pass may a distinct `R` be created.
The `S`-to-`R` diff is limited to filling that readiness manifest and changing
existing release-plan checklist items from `[ ]` to `[x]`. `S` must be an
ancestor of `R`. Any other source, documentation, workflow, or metadata change
requires a new `S` cycle and fresh review.

Candidate dispatch uses the full 40-character `R` SHA with
`expected_tag=v0.2.5` and the configured evidence path. Before dispatch, the
checked-out source and both protected branch tips must equal exact `R`. The
official workflow must qualify the same-`S` reviewed code and exact-`R`
artifacts. It must pass verify, build, smoke, every applicable qualification
aggregate, the historical 62+12 gate, and evidence collection before creating
the non-draft, non-prerelease GitHub Release. PyPI publication depends on a
successful Release creation and readback. Manual dispatch remains candidate-
only and does not create a Release or publish to PyPI.
