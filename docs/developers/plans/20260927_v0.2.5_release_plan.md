# v0.2.5 Release Plan

Status: preparation in progress
Release decision: **HOLD**

## Release scope

This patch release carries the public cross-format I/O hardening merged in #751.
The frozen 74-scenario audit evidence and ZIP remain historical inputs. The
candidate must exercise the exact built wheel and sdist across Python 3.11 and
3.12 in base and optional-backend environments. Optional cells install the
declared `io`, `netcdf4`, and `zarr` extras. Base cells must prove `zarr`, `xarray`,
and `netCDF4` are absent with `importlib.util.find_spec()`.

The review baseline is the peeled v0.2.4 release source
`522e52a082925da4dd37966d82a7616bdd2a5248`. Every changed path between
that source and candidate S, including both rename endpoints, must belong to a
v0.2.5 review lane. This covers #751 source paths and release prep.

## Candidate and approval rules

Freeze S with the byte-exact empty JSON evidence block at
`docs/developers/plans/manifests/audit-manifest-v0.2.5-release-readiness.yaml`.
Obtain same-S approvals for all review lanes. The release owner then records a
separate `human_approval` object for the scientific/data-model lane. Its
`comment_id` must resolve through GitHub's Issues Comments API to a comment by
`tatsuki-washimi`, with the same UTC timestamp, reviewed commit, scope digest,
and `APPROVED` verdict.

Only after approvals, create distinct R by changing readiness evidence and
transitioning existing plan checkboxes from `[ ]` to `[x]`. S must be an
ancestor of R. No other S-to-R changes are allowed. Candidate dispatch uses
R's full SHA as `release_ref` and checks the evidence's S against R.

## Release metadata

The selected metadata date is 2026-09-27 UTC. If publication moves to a later
UTC date, update all release dates before S freeze, then repeat review and
qualification. Never backdate a tag.

## Release gates

- [x] Candidate S covers the full diff from peeled v0.2.4 source and all three
      review lanes approve that same S with matching scope digests.
- [x] Release-owner approval is verified against the configured scope and
      canonical v0.2.5 comment tokens.
- [ ] Release metadata, source/tag binding, S-to-R delta, protected refs,
      and two-file SHA-256 payload contract pass.
- [ ] Four-cell smoke and 19-cell qualification aggregates pass for R.
- [ ] Separate four-cell DiagGUI aggregate passes with the existing exact test
      nodes and base/dttxml semantics.
- [ ] Eight-cell cross-format I/O aggregate passes: Python 3.11/3.12 ×
      wheel/sdist × base/optional, with validated backend presence.
- [ ] All four aggregates gate candidate GO and strict tag publication.
- [ ] Recheck release dates and all gates before tagging; any source or date
      change requires a new S and fresh evidence.
