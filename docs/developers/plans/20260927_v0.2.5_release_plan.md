# v0.2.5 Release Plan

Status: expanded candidate preparation in progress
Release decision: **HOLD**

## Release scope

This patch release carries the public cross-format I/O hardening merged in
#751 and the measured internal I/O performance and scalability work under
[#580](https://github.com/tatsuki-washimi/gwexpy/issues/580). The latter is
patch-eligible only where it adds no public API, dependency, or persistence
schema and preserves public numerical results, dtype, metadata, warning/error
behavior, and on-disk format, except for the separately gated #589 and #585
SDB snapshot exceptions below. An additional observable divergence requires
its own review, approval, and disclosure before inclusion.

The performance scope is the #581 benchmark harness; #582 merge, #583
dispatch, #584 HDF5/NetCDF/Zarr range reads, #585 CSV/SDB/TDMS, #589 native
DTTXML, and #588 GWF scalability; the NumPy-only portion of #518; and the
dtype-preserving portion of #586. #587, #590, #519, Numba, and the remaining
parts of #518/#586 are excluded. The external `dttxml` route is unchanged and
outside the #589 performance claim.

For #589, parser-level use of already accepted selectors may omit warnings
and decode errors arising exclusively from fully unselected DTTXML payloads
on the native parser route. XML structural errors and selected-payload
behavior must remain equivalent to the old R baseline. This exception needs
separate human scientific/data-model approval for S2 and disclosure in both
`CHANGELOG.md` and `release_notes/v0.2.5.md`. It does not enlarge #611's
`non_intersecting_window_safety` exception, which applies only to completely
disjoint plain HDF5 read windows.

For #585 SDB reads, pin whole-table time/unit validation and the selected
payload query to one SQLite read transaction. The deterministic B1 preflight
schedule commits valid selected `outTemp` from 60 to 99 °F between validation
and payload query, with schema, time, unit, and validation inputs unchanged.
Old R returns 37.22222222222222 °C from the later value, whereas the
single-snapshot read returns 15.555555555555555 °C from the earlier value.
The proposed correctness exception covers value, warning, and error differences
caused by a WAL writer committing after the reader pins its snapshot. Before
SDB runtime edits, freeze an append-only B1 fault matrix for selected and
unselected payload updates, timestamp and `usUnits` changes, schema changes,
and malformed values. Preserve old-R behavior for static sources, including
their malformed-data warnings and errors. Disclose the exact characterized
concurrent difference in the changelog and release notes, and require separate
review and human scientific/data-model approval before S2 can qualify.

The frozen 74-scenario audit evidence and ZIP remain historical inputs. The
new candidate must run these scenarios on its exact built artifacts, along
with the current GWpy/DiagGUI and release gates. Optional cells install the
declared `io`, `netcdf4`, and `zarr` extras. Base cells must prove `zarr`,
`xarray`, and `netCDF4` are absent with `importlib.util.find_spec()`.

The review baseline is the peeled v0.2.4 release source
`522e52a082925da4dd37966d82a7616bdd2a5248`. Every changed path between
that source and S2, including both rename endpoints, must belong to a v0.2.5
review lane. This covers #751 source paths, all performance lanes, and release
prep. Freeze B1 from old R `1eb2cd62c365a7ed3252ed1b1fe82f9265c5ef1c`
before any runtime work in each lane; retain the frozen evidence and compare
the integrated S2 candidate against it under the same harness and environment.

## Historical S/R evidence and new candidate rules

The 2026-09-27 S/R cycle is historical and superseded for this expanded scope.
Old S was `ef7d144fe5464ddc5ddc23cb29064f93edd7f06f`; old R was
`1eb2cd62c365a7ed3252ed1b1fe82f9265c5ef1c`. Its three same-S reviews,
release-owner approval, and completed checklist items apply only to old S/R.
The recorded approval does not cover #589 or the SDB snapshot difference, or
grant S2 approval or release GO.
The old readiness manifest is historical evidence until replaced for S2/R2.

Set a new UTC metadata date immediately before freezing S2. Freeze S2 with
the byte-exact empty JSON evidence block at
`docs/developers/plans/manifests/audit-manifest-v0.2.5-release-readiness.yaml`.
Obtain independent `scientific-data-model`, `documentation`, and
`release-security` reviews of that same S2 SHA with matching scope digests.
The release owner then records a separate `human_approval` object that
explicitly covers both the #589 native-parser exception and the #585 SDB
snapshot correction, as well as the reviewed S2 scope.
Its `comment_id` must resolve through GitHub's Issues Comments API to a
comment by `tatsuki-washimi`, with the same UTC timestamp, reviewed commit,
scope digest, and `APPROVED` verdict. Prior comments cannot be rebound to S2.

Only after these reviews and approval, create distinct R2 by changing
readiness evidence and transitioning existing plan checkboxes from `[ ]` to
`[x]`. S2 must be an ancestor of R2. No other S2-to-R2 changes are allowed.
Candidate dispatch uses R2's full SHA as `release_ref` and checks the
evidence's S2 against R2.

## Release gates

- [ ] Every performance lane has a frozen, source-bound B1 baseline before
      runtime changes and passes its correctness, structural, and declared
      performance/resource gates; #589 and #585 SDB exceptions stay within
      their separately approved scopes.
- [ ] Candidate S2 covers the full diff from peeled v0.2.4 source and all
      three independent review lanes approve that same S2 with matching scope
      digests.
- [ ] Separate human scientific/data-model approval explicitly covers the
      #589 and #585 SDB exceptions and is verified against the configured scope
      and canonical v0.2.5 comment tokens.
- [ ] Release metadata, source/tag binding, S2-to-R2 delta, protected refs,
      and two-file SHA-256 payload contract pass.
- [ ] The 74 audit scenarios and GWpy/DiagGUI checks pass on R2's exact
      installed artifacts; Ruff, MyPy, pytest, and documentation checks pass
      on the matching R2 source and applicable installed artifacts.
- [ ] Four-cell smoke and 19-cell qualification aggregates pass for R2.
- [ ] Separate four-cell DiagGUI aggregate passes with the existing exact test
      nodes and base/dttxml semantics.
- [ ] Eight-cell cross-format I/O aggregate passes: Python 3.11/3.12 ×
      wheel/sdist × base/optional, with validated backend presence.
- [ ] All four aggregates gate candidate GO and strict tag publication;
      the release owner records GO only after exact-R2 qualification passes.
- [ ] Recheck release dates and all gates before tagging; any source or date
      change requires a new S2 and fresh evidence.
