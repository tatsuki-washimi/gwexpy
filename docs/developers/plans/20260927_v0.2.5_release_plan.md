# v0.2.5 Release Plan

Status: S7/R7 corrective candidate preparation in progress
Release decision: **HOLD**

## Release scope

This patch release carries the public cross-format I/O hardening merged in
#751 and the measured internal I/O performance and scalability work under
[#580](https://github.com/tatsuki-washimi/gwexpy/issues/580). The latter is
patch-eligible only where it adds no public API, dependency, or persistence
schema and preserves public numerical results, dtype, metadata, warning/error
behavior, and on-disk format, except for the separately gated #589 and #585
SDB snapshot exceptions below. An additional observable divergence requires
its own review, approval, and disclosure before inclusion.

The performance scope is the #581 benchmark harness; #582 merge, #583
dispatch, #585 CSV/SDB/TDMS, #589 native
DTTXML, and #588 GWF scalability; the NumPy-only portion of #518; and the
dtype-preserving portion of #586. #587, #590, #519, Numba, and the remaining
parts of #518/#586 are excluded. The external `dttxml` route is unchanged and
outside the #589 performance claim.

#584 HDF5/NetCDF/Zarr range push-down is evidence-only and **HOLD** for this
candidate. The frozen B1 baseline raises on a corrupt chunk even outside the
requested window in all four tested format routes. Skipping that chunk would
remove an existing error; reading it would fail the predeclared selected-chunk
byte bound. No #584 runtime change is included, and neither #589 nor #611
authorizes an exception for it.

For #589, parser-level use of already accepted selectors may omit warnings
and decode errors arising exclusively from fully unselected DTTXML payloads
on the native parser route. XML structural errors and selected-payload
behavior must remain equivalent to the old R baseline. This exception needs
separate human scientific/data-model approval for S7 and disclosure in both
`CHANGELOG.md` and `release_notes/v0.2.5.md`. It does not enlarge #611's
`non_intersecting_window_safety` exception, which applies only to completely
disjoint plain HDF5 read windows.

For #585 SDB reads, pin whole-table time/unit validation and the selected
payload query to one SQLite read transaction. The deterministic B1 preflight
schedule commits valid selected `outTemp` from 60 to 99 °F between validation
and payload query, with schema, time, unit, and validation inputs unchanged.
Old R returns 37.22222222222222 °C from the later value, whereas the
single-snapshot read returns 15.555555555555555 °C from the earlier value.
The proposed correctness exception covers value, warning, and error differences
caused by a WAL writer committing after the reader pins its snapshot. Before
SDB runtime edits, freeze an append-only B1 fault matrix for selected and
unselected payload updates, timestamp and `usUnits` changes, schema changes,
and malformed values. Preserve old-R behavior for static sources, including
their malformed-data warnings and errors. Disclose the exact characterized
concurrent difference in the changelog and release notes, and require separate
review and human scientific/data-model approval before S7 can qualify.

The frozen 74-scenario audit evidence and ZIP remain historical inputs. The
new candidate must run these scenarios on its exact built artifacts, along
with the current GWpy/DiagGUI and release gates. Optional cells install the
declared `io`, `netcdf4`, and `zarr` extras. Base cells must prove `zarr`,
`xarray`, and `netCDF4` are absent with `importlib.util.find_spec()`.

The review baseline is the peeled v0.2.4 release source
`522e52a082925da4dd37966d82a7616bdd2a5248`. Every changed path between
that source and S7, including both rename endpoints, must belong to a v0.2.5
review lane. This covers #751 source paths, all performance lanes, and release
prep. Freeze B1 from old R `1eb2cd62c365a7ed3252ed1b1fe82f9265c5ef1c`
before any runtime work in each lane; retain the frozen evidence and compare
the integrated S7 candidate against it under the same harness and environment.
