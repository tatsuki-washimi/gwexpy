# v0.2.3 GWpy 既定挙動互換性の安定化

Status: in-progress

## Goal

この計画は、GWpy 4.0.1 と 4.0.2 が正常に観測可能な既定挙動を、GWexpy v0.2.3 の既定経路で安定させるための patch-only release 計画である。

対象読者は、GWpy 対応 API、I/O、CI qualification を変更または審査する開発者である。

GWpy が有限な値を返して正常終了する既存 API では、GWexpy も値、shape、選択 sample、軸、成功または例外の種別を一致させる。

例外の比較は成功または失敗と exception class を対象とし、例外 message は public contract または既存 upstream test が要求するときだけ比較する。

NaN と Inf を含む配列は、`isnan`、`isposinf`、`isneginf` の mask をそれぞれ独立に比較し、残る有限値部分だけを fixture 固有の数値比較器で比較する。

本 release は presentation-only の plot 差異を対象外とし、新しい public API、依存関係、データ format を追加しない。

Issue #634 の CSV 全時刻 scale、#688 の full rational axis、SeriesMatrix、GUI、性能機能の作業はこの release から除外する。

## Architecture

GWexpy の既定 API は GWpy 互換の親実装を最初の経路とする。

GWexpy 固有機能は、GWpy が扱わない入力または明示的な既存 helper に限定して別経路に入れる。

native HDF5 および CSV の標準経路は、GWpy oracle が成功する場合に同じ論理 topology と可視結果を持つ。

private exact-time sidecar は後方互換性のために保持できるが、GWpy から可視な group、path、native attribute、payload topology を変えてはならない。

互換性判断は、実装 branch 上の GWexpy と、別々に導入した GWpy 4.0.1 および 4.0.2 oracle の differential test で記録する。

## 公開挙動の決定

### #639 の完全閉包

inventory の母集団は、MRO に GWpy class を持つ public GWexpy class の、すべての effective public GWexpy API member と `__new__`、`__init__` である。

public root は explicit export から決め、private、GUI、internal backend、Mixin、Base、Core、Protocol、MetaData class を除外する。

各 root について、最初の GWpy class に達する前の GWexpy MRO prefix を `vars()` と static descriptor で walk する。

この walk には function、classmethod、staticmethod、property と各 accessor、generic descriptor、統合された `read`/`write` descriptor を含める。

public member alias と影響を受ける subclass は個別に保持する。

`implementation_group` は evidence の再利用だけに使い、logical class/member row を減らす理由にしない。

GWpy counterpart の解決は、GWexpy を一度も import していない pristine subprocess で行う。

GWexpy が collection method を四つ GWpy へ inject するため、GWexpy import 後の process を counterpart 判定に使うと母集団を誤る。

planning-time research の初期値は、public root 16 個、logical class/member candidate 573 個、pristine counterpart 132 個、GWexpy-only 441 個、constructor 11 個である。

構造は GWpy 4.0.1 と 4.0.2 で同一だった。

この数は計画時点の発見値であり、release 前の regeneration を authoritative とする。

stable case row key は `(public_class, member, GWpy version, fixture)` とする。

inventory の一行は public class、member、alias、affected subclass、定義 source、MRO 上の pristine GWpy counterpart、GWexpy override、GWpy version、fixture、GWpy/GWexpy observation、比較器、test または evidence、issue、terminal state を記録する。

terminal state は `fixed`、`no-finding`、`GWpy-fails`、`GWexpy-only` の四つだけである。

作業中だけは `unreviewed` と `differential-required` を使えるが、release candidate の inventory では件数を必ず 0 にする。

`GWexpy-only` は pristine subprocess で counterpart が存在しない証拠を必要とする。

`GWpy-fails` は concrete fixture と GWpy exception class を必要とする。

`no-finding` は oracle differential evidence を必要とする。

`fixed` は pre-fix mismatch、対応 issue、green test、対応 evidence を必要とする。

確認済みの patch defect を deferred にしない。

default がすでに compatible である場合だけ、minor follow-up を本 release 後の別 issue にできる。

### HDF5 append の native 契約

Phase 0 の最初の red test は、`TimeSeriesDict` HDF5 append で既存 data が失われる事例とする。

native/default の read/write/append/overwrite は、oracle と names、group、append、overwrite、logical keys、topology、成功または例外 class を比較する。

oracle が colon または slash を含む name で失敗する場合、GWexpy が成功する必要はない。

exact sidecar は private augmentation とし、GWpy-visible topology、path、native attribute を変更しない。

旧 manifest は読み続けられなければならない。

custom append は既存 payload を truncate してはならない。

### constructor の routing

親例外を routing または retry の判定に使わない。

GWpy が support する input class と calling form は変更せず一回だけ parent に渡す。

GWexpy-only の time-like input は、parent 呼出前の明示的な type predicate と routing predicate で normalizer に送る。

parent が処理した input は retry しない。

positional epoch と keyword epoch は同じ classifier を通す。

`t0_ns` は独立した exact authority のままとし、矛盾する指定は拒否する。

`TimeSeries(x, None, 1000, 1 * u.ms)` と、同じ値を keyword で渡す form は等価であることを test する。

### 時刻 API

Issue #709 の `to_gps`、#710 の date component、#711 の `tconvert` gps-or-date を GWpy default と比較する。

3 から 7 要素の numeric tuple/list で date-shaped な input は GWpy に送り、`(2017, 13, 1)` のような不正 date は vector fallback せず GWpy の失敗を保つ。

明示的 vector input は GWexpy extension として維持する。

Phase 3 で `from_gps` の scalar success fixture、numeric string、LIGOTimeGPS-like input、fractional GPS、leap-second 近傍、該当する supported GWexpy vector input の differential evidence を採る。

Phase 4 は、その結果の terminal manifest state を記録し検証するだけであり、`from_gps` fixture を再実行する phase ではない。

観測可能な差異がなければ `no-finding` を terminal state にする。

### `FrequencySeries.ifft`

`FrequencySeries.ifft` は parent が返す `t0` と `dt` を保つ。

absolute time から cadence を再構成しない。

4 Hz、4096 Hz、1 MHz、10 MHz、odd/even length、large GPS epoch の fixture を比較する。

### spectral API

Issue #698 の CSD default unit は parent の unit を保持する。

Issue #699 の default Rayleigh は GWpy と一致させ、補正 helper を public API にしない。

Issue #702 の steady path の `epsilon=None` は GWpy と一致させ、transient と explicit `epsilon` は既存 extension とする。

Issue #703 は API ごとに differential test を採り、wholesale な guard removal をしない。

### plot の positional layout

次の positional layout を keyword 呼出と同じ binding にする。

| API | positional layout | 成功 fixture |
| --- | --- | --- |
| `TimeSeries.plot` | `method, figsize, xscale` | `ts.plot('plot', (10, 4), 'linear')` |
| `FrequencySeries.plot` | `method, xscale` | `fs.plot('plot', 'linear')` |
| `Spectrogram.plot` | `method, figsize, xscale` | `spec.plot('imshow', (10, 6), 'linear')` |
| `TimeSeriesDict.plot` | `label, method, figsize, xscale` | `tsd.plot('name', 'plot', (10, 4), 'linear')` |

duplicate argument と excess positional argument は、GWpy と成功または失敗、exception class を比較する。

`step` は GWpy が失敗する場合があるため、GWpy 成功 fixture として扱わない。

pixel または style の比較は行わない。

### CSV routing

次の route table を既定契約とする。

| 操作 | 条件 | 経路 |
| --- | --- | --- |
| TimeSeries read | plain `.csv` または `format='csv'`、かつ `config`、`channels`、`timezone`、`resample`、`resample_method` が明示されない | GWpy native |
| TimeSeries read | enhanced-only key のいずれかが明示される | 既存 enhanced reader |
| direct CSV helper | 常に | 既存 enhanced reader |
| TimeSeries write | 標準 `TimeSeries.write(..., format='csv')` | GWpy native に args/kwargs を forward |
| enhanced CSV write | direct existing helper | 既存 enhanced writer |
| FrequencySeries ordinary CSV | 標準呼出 | GWpy native |

complex CSV は write outcome、出力、exception class を比較する。

roundtrip は GWpy 自身が成功する fixture だけで比較する。

### collection API

collection `crop` は self を mutate し、同じ self を返す。

`prepend` は key-wise に動作する。

`filterba` shim の historical call-shape evidence は、GWpy tag `v3.0.14`、commit `9a0113d49016a3231fca6db78af789ca46c15599`、`gwpy/frequencyseries/frequencyseries.py` の 322-326 行から先に記録する。

historical signature は `filterba(self, *args, **kwargs)` であり、`DeprecationWarning` を発して、変更しない `args`/`kwargs` を `filter` に委譲する。

relevant underlying defaults は `analog=False` と `inplace=False` である。

GWpy 4.0.1 と 4.0.2 は behavioral oracle のままとし、どちらにも parent `filterba` がないことを確認する。

GWpy v3.0.14 は historical call-shape evidence のためだけに使い、v0.2.3 の behavioral oracle に置き換えない。

## Testing and release gates

各 inventory fixture は GWpy version、input、GWpy observation、GWexpy observation、値/metadata comparator、test path、issue、inventory state を evidence に記録する。

comparator は fixture ごとに名前を持ち、approximate float または complex comparison には明示的な `rtol` と `atol` を持たなければならない。

comparator または必要な tolerance が欠ける fixture は invalid とする。

全 API に適用する一つの global tolerance は定めない。

unit metadata は installed GWpy oracle の `Unit` と exact equality で比較する。

単に convertible であることは parity ではない。

diagnostic conversion は unit mismatch を evidence に記録した後だけに許し、判定を一致へ変えない。

shape と dtype は oracle/version ごとに exact でなければならない。

integer、bool、string、sample selection は exact comparison を使う。

axis quantity は exact `Unit` と fixture 固有の numeric comparator を併用する。

`t0_ns` は integer exact comparison を使う。

NaN/Inf を含む数値配列は `isnan`、`isposinf`、`isneginf` の各 mask を別々に比較し、有限値部分だけに fixture 固有 comparator を適用する。

required compatibility/qualification test に新しい skip が一つでも発生した場合、または approved expected-skip baseline にない skip が一つでもある場合、それを **unexpected skip** と定義する。

既にその baseline に記録済みの optional-dependency skip は許容する。

candidate evidence は baseline SHA-256 と cell ごとの observed canonical skip set を明記する。

required observed skip は空でなければならず、optional observed skip はその cell の approved baseline の subset でなければならない。

release candidate には `unreviewed`、`differential-required`、unexpected failure、unexpected skip がいずれも 0 であることを要求する。

local gate は次の順で実行する。

1. Phase ごとの GWpy 4.0.1/4.0.2 focused differential tests。
2. HDF5 append、constructor、time、FFT、spectral、plot、CSV、collection focused tests。
3. `conda run -n gwexpy pytest tests -q`。
4. `conda run -n gwexpy ruff check gwexpy tests`。
5. `conda run -n gwexpy mypy gwexpy`。
6. `conda run -n gwexpy ruff format --check gwexpy tests`。
7. strict documentation build、`git diff --check`、package build、`twine check --strict`。

CI gate は既存の 19 cell を実際に実行し、各 job の実行結果、同一 artifact digest、skip baseline SHA-256、cell ごとの observed canonical skip set、qualification evidence を candidate SHA に結び付ける。

外部 CI、人間 review、tag、PyPI publication は本 worktree の実装権限外であり、candidate が全 gate を満たしてから別工程で実施する。
