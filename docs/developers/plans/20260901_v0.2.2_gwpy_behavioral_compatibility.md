# v0.2.2 GWpy 既定挙動互換性・再 qualification

Status: implementation complete — release HOLD

## 目的

GWpy 対応 API が正常な有限値を返す場合、GWexpy の既定設定でも値、sample 選択、軸情報、正常終了を一致させる。

数値的な差異は GWexpy 固有 API または将来の明示的 opt-in に限定する。

このrelease固有の実装判断は、プロジェクト横断の
[GWpy behavioral compatibility policy](../../../docs_redesign/explanation/gwpy_compatibility_policy.md)
に従う。

## 互換性契約

- GWpy が受理する `TimeSeries.crop()` の引数は GWpy 実装へ委譲する。
- GWpy が扱わない追加時刻型だけを GWexpy の時刻正規化経路へ送る。
- exact HDF5 marker と sidecar は保持するが、既定演算の値、index、`t0`、`dt`、成否へ介入させない。
- base 演算の完了後、`dt` が整数 nanosecond の場合だけ派生 exact epoch を伝播する。
- `dt` が整数 nanosecond で表現できない場合は派生 exact authority を破棄し、slice と crop は失敗させない。
- 不正または矛盾した exact metadata は異常入力であり、既存の fail-closed 検証を維持する。
- HDF5 は native GWpy-compatible payload を読み、valid marker の exact 値を既存の `t0_gps_ns` から取得可能にする。
- v0.2.2 では `exact_time=True` などの新しい public 引数を追加しない。

## 実装

### P0: crop と exact state

- `TimeSeriesCore.crop()` の標準引数を GWpy へ委譲する。
- `TimeSeries.__getitem__()` は base slice 中に private exact state を選択処理から隔離する。
- base slice の完了後にだけ exact state を再構成する。
- 4 Hz、4,096 Hz、1 MHz、10 MHz の exact HDF5 系列を GWpy と比較する。
- sample 境界の直前、一致、直後について crop、slice、bounded read を比較する。

### P1: lazy registration

- plain import と constructor-only 利用は I/O package をロードしない。
- scalar、collection、matrix の最初の明示 I/O は同一の idempotent bootstrap を通る。
- 反復 I/O、reload、format 順序変更後も reader、writer、identifier の登録順と identity を維持する。
- `scripts/benchmarks/bootstrap_io_benchmark.py` で plain import、constructor-only、first HDF5 I/O、repeated HDF5 I/O を fresh subprocess で測定する。
- 性能結果は自動 threshold にせず、maintainer が改善または許容可能と記録した場合だけ GO とする。
- 30 回 A/B 測定の集約値は `manifests/v0.2.2-bootstrap-io-performance.json` に記録する。

### Release identity

- package、CHANGELOG、CITATION、Zenodo metadata を `0.2.2` に揃える。
- `scripts/ci/release_contracts.json` に v0.2.2 の review lane と protected ref を登録する。
- release workflow は payload を一度だけ build し、全 qualification cell が同一 digest の wheel と sdist を使う。
- publish job は全 cell と evidence job の成功後に同じ payload bytes だけを PyPI へ送る。
- 公開済み `v0.2.1` tag は移動または削除しない。

## Qualification gate

ローカル gate は次の順に実行する。

1. P0、P1、GWpy compatibility の focused tests。
2. `conda run -n gwexpy pytest tests -q`。
3. `ruff check gwexpy tests`。
4. `mypy gwexpy`。
5. `ruff format --check gwexpy tests`。
6. strict docs build と `git diff --check`。
7. wheel と sdist の build、metadata check、`twine check --strict`。

GitHub gate は 19 cell を実行し、unexpected failure と skip が 0 であり、全 cell の payload digest が同一であることを evidence に記録する。

scientific compatibility review、performance evidence review、release-security review の三 lane がすべて承認されるまで release status は HOLD とする。

## Release operation boundary

この作業では code、test、workflow、release metadata、qualification evidence の候補を作成する。

branch merge、protected branch 更新、annotated tag 作成、workflow dispatch、PyPI 公開、GitHub Release、Zenodo 公開は人間の承認後に別工程で行う。

tag 作成前に PyPI Trusted Publisher、GitHub `pypi` environment、tag ruleset を readback し、認可不備があればタグを作成せず HOLD を維持する。
