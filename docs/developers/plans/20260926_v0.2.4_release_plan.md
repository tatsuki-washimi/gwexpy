# v0.2.4 Release Plan

Status: in progress
Release decision: **HOLD**

## Release scope

This patch release records the DiagGUI XML reader work for issues #726 and
#730–734. The candidate must preserve the characterized serialized values,
frequency and time axes, complex phase, and reader-selection behavior. The
release does not infer physical units, calibration direction, or FFT
normalization where the input does not state them.

The review baseline is the peeled v0.2.3 release source
`75d3d1a89ebc8942af1f3228152fea99d2d3420e`. Every changed path between that
source and candidate S must belong to at least one v0.2.4 review lane. Rename
checks include both the old and new path. The scientific/data-model lane covers
`gwexpy` and `tests/io`; documentation and release-control lanes cover their
corresponding source, configuration, and tests.

## Candidate and approval rules

Freeze S with the byte-exact empty JSON evidence block at
`docs/developers/plans/manifests/audit-manifest-v0.2.4-release-readiness.yaml`.
Obtain same-S approvals for all review lanes. The release owner then records a
separate `human_approval` object for the scientific/data-model lane. Its
`comment_id` must resolve through the GitHub Issues Comments API to a comment
by `tatsuki-washimi`, with the same UTC timestamp, reviewed commit, scope digest,
and `APPROVED` verdict.

Only after those approvals, create a distinct R that changes the readiness
evidence and transitions existing plan checkboxes from `[ ]` to `[x]`. The
reviewed S must be an ancestor of R. No other S-to-R changes are allowed.
Candidate dispatch uses R's full SHA as `release_ref`; the workflow must bind
the evidence's S to that exact R before qualification or publication jobs can
continue.

## Release metadata

The selected metadata date is 2026-09-26 UTC. If publication moves to a later
UTC date, update all release dates, freeze a new S, and repeat review and
qualification. Do not backdate a tag.

## Release gates

- [x] Candidate S is the exact release scope after the v0.2.3 peeled source;
      all changed paths, including both rename endpoints, are covered by review
      lanes.
- [x] Scientific/data-model, documentation, and release-security reviews are
      approved for the same S and each scope digest matches S's tree.
- [x] Release-owner approval is recorded by comment ID and verified against
      GitHub's API for the configured scientific/data-model scope.
- [ ] Release metadata, candidate identity, exact S-to-R delta, protected
      branch tips, and artifact contracts pass the release workflow.
- [ ] Candidate-wide tests and the fresh qualification and smoke evidence pass
      for the exact R.
- [ ] Before tagging, recheck the metadata date and all required release
      controls. Any source or date change requires a new S and fresh evidence.

  embedded/nonuniform frequency axes and sample precision.
- #730 adds the characterized native fallback for DiagGUI TimeSeries products.
