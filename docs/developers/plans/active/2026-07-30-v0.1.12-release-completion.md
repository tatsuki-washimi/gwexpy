## Lane B: generator PR 契約

`tools/gen_release_notes.py` を単一version CLI に改修する。

### CLI インターフェース

```bash
python tools/gen_release_notes.py --version 0.1.11
# → release_notes/v0.1.11.md のみ上書き
```

### 必須保証

- 指定 version section のみ抽出・生成（他 version の release_notes を変更しない）
- `Unreleased` セクションを除外
- 指定 section が 0 件 → 非ゼロ exit（fail-closed）
- 指定 section が複数件 → 非ゼロ exit（fail-closed）
- 出力: UTF-8、LF 改行、末尾改行 1 個
- 同一入力 → byte-identical 出力

### 必須 contract tests（9 件）

1. `v0.1.11` golden（既存 `release_notes/v0.1.11.md` との byte-identical 一致）
2. 指定 version のみ変更（他 version ファイルに diff なし）
3. `Unreleased` を指定しても除外（fail-closed）
4. 存在しない version を拒否（非ゼロ exit）
5. version heading 重複を拒否（非ゼロ exit）
6. 後続 version との境界が正確に抽出される
7. CRLF 入力 → LF 出力
8. 末尾改行 0 個または複数個 → 1 個に正規化
9. 2 回実行して差分なし（`git diff --exit-code` 相当）

### TDD 順序

1. 現行抽出ロジックに contract tests を追加（通る部分は維持）
2. 単一version CLI と fail-closed 検査を追加
3. 曖昧抽出・欠落・重複ケースで失敗する箇所のみ修正

## Lane G: #511 実装詳細

### スコープ（CI 限定、ライブラリ本体・公開 API 変更なし）

#### interop-mne zero-test 防止

- pytest 収集数が 0 なら失敗（exit code 5 を成功扱いしない）
- wrapper が exit code を隠す場合、JUnit XML の `tests` 合計が 1 以上であることを後段で検査
- skip だけで実行対象 0 になったケースも fail-closed
- 「workflow が緑だが実際にはテストしていない」状態を禁止

#### JUnit 集約

- 各 gate/matrix/shard が固有名の JUnit XML を生成
- 各 XML を固有 artifact 名で upload
- 集約 job が期待する全 suite を download
- 以下を失敗条件: 期待 suite 欠落、XML parse 失敗、suite 名重複、tests 合計 0、failure/error
- suite 別の tests/skipped/failures/errors と総計を job summary へ出力
- artifact upload が `if: always()` でも、テスト失敗を最終成功へ変換しない

### 必須 contract tests（6 件）

1. 正常な複数 JUnit XML の集約
2. 1 suite 欠落 → 失敗
3. 空 suite（tests=0）→ 失敗
4. malformed XML → 失敗
5. failures/errors を含む suite → 失敗
6. duplicate suite → 失敗

### 注意

- physics sign-off 不要
- 主な変更候補: interop workflow、gate runner または JUnit 集約用の小さな script、unit/contract tests
