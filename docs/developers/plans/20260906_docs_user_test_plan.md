# GWexpy公開Docsの実ユーザー試験計画

作成日：2026-09-06（JST）

状態：実施前

## 目的と対象

公開Docsを、実際の利用者がどこで止まるかという観点から評価する。

今回の試験では、次の三つの利用行動を測定する。

- トップページから自分に合う入口を選ぶ。
- Installationを読み、GWexpyをimportできる環境を用意する。
- Quickstartを実行し、最初の`asd.png`を保存して結果を説明する。

ベースラインは、2026-09-06時点で確認した公開Docsのソース`1ff2cb99cc5a6013417cd5e3d147e1d21631e9e7`とする。
開始URLは`https://tatsuki-washimi.github.io/gwexpy/docs/`とする。
セッション開始前に`build-info.json`の`source_revision`とサイトのdeploy記録を読み、実際に配信されているSHAを記録する。
記録がベースラインと異なる場合は、ベースラインの観察結果と混ぜず、実際のSHAを別の試験単位として扱う。
導入するGWexpyは現行リリース`v0.2.3`とし、旧版を意図的に使わない。
DocsのソースSHA、Docsに表示された版、インストールされたパッケージ版は別々に記録する。

この段階では公開Docsを変更しない。
実験データ、認証情報、参加者の業務データは使わず、Docsに用意された合成データ例だけを使う。

## 参加者と環境

参加者は4名とする。

| 匿名ID | 背景 | 共通課題 | 追加課題 |
| --- | --- | --- | --- |
| P01 | Python、スペクトル解析、GWexpyの初心者 | 入口選択、導入、Quickstart | なし |
| P02 | Python、スペクトル解析、GWexpyの初心者 | 入口選択、導入、Quickstart | なし |
| P03 | GW実験またはCommissioner | 入口選択、導入、Quickstart | GUIでのチャンネル選択、区間選択、ASD、coherence、条件保存に対応する例 |
| P04 | Scientific PythonまたはGWpy | 入口選択、導入、Quickstart | 配列と辞書から`TimeSeries`と`TimeSeriesDict`への対応、単位の対応 |

参加者は、英語版と日本語版のどちらを使うか自分で選ぶ。
言語、ブラウザ、OS、Pythonの有無、既存のGWexpy経験を匿名記録に残す。

参加者自身の実機ブラウザを使い、ブラウザプロファイルとGWexpy用Python環境は新規にする。
Python 3.11とpipが既に使える場合は、新しい仮想環境を参加者自身に作成してもらう。
Pythonまたはpipがない場合は、その事実を環境上の阻害要因として記録し、OSへの導入で試験が止まらないよう、モデレーターが空のPython 3.11環境を用意してDocsの評価を続ける。
この介入は、時刻とともに記録する。

試験は画面共有を基本とし、画面録画と音声録音は明示的な同意がある場合だけ行う。
同意がない場合は、モデレーターが記録表に操作と発話を要約する。

## セッション台本

1セッションは30から40分とする。
モデレーターは解答やページ名を先に示さず、全員に同じ順序で課題を提示する。

### 共通課題

開始時には、次の文面と公開トップページのURLだけを渡す。

```text
合成された2チャンネルの信号を解析し、周波数ごとの揺らぎを図として保存してください。
トップページから始めてください。
```

次の時刻を測る。

1. 課題提示から、利用者が妥当な入口を選ぶまで。
2. Installationを開いてから、`import gwexpy`が成功するまで。
3. 環境が使える状態になってから、`asd.png`を保存するまで。

Quickstartでは、optional packageを追加せず、合成された二つのチャンネルのASD図を保存する。
再実行を一度行い、同じ成果物を再現できるか確認する。

図を保存した後、参加者に次の四点を自分の言葉で説明してもらう。

- 横軸と縦軸が表す量。
- 40 Hz付近のピークが表す信号。
- `fftlength=2`から分かる周波数ビン幅。
- ASDのピーク高さを元のsine振幅と同一視できない理由。

### 経験者向け追加課題

P03には、Commissionerのシナリオを提示する。

```text
GUIで見ていた2チャンネルの解析を、同じ条件で再実行できるPythonの作業に置き換えてください。
```

参加者がExperimentalistとCommissionerのどちらの入口を選ぶかを観察し、その後、`commissioner.py`を使ってデータ読み込み、区間選択、ASDとcoherenceの比較、図と`analysis-parameters.json`の保存まで進めてもらう。
coherenceの高さだけから結合方向を判断していないかも確認する。

P04には、Scientific Pythonのシナリオを提示する。

```text
サンプル配列とチャンネル辞書を、時刻と単位を失わずにGWexpyへ移し、チャンネルごとのスペクトルを計算してください。
```

`scientific_python`の対応例を使い、`ndarray`と`TimeSeries`、辞書と`TimeSeriesDict`、`nperseg`のサンプル数と`fftlength`の秒という差を説明してもらう。

### モデレーターの介入

参加者が2分間進展しない場合だけ、次の中立的な問いを使う。

```text
いま何を探していますか。
```

それでも進まない場合は、解決に必要な最小限の支援を行う。
支援したページ名、発話、時刻を記録し、完了時間とは別に扱う。
外部検索や他の教材の利用は妨げないが、利用先と利用時刻を記録する。

## 記録項目と判定

匿名IDごとに、次の項目を記録する。

| 区分 | 記録項目 |
| --- | --- |
| 背景 | 匿名ID、背景、選択言語、OS、ブラウザ、Pythonとpipの事前状態 |
| 入口 | 最初に選んだカード、妥当な入口までの秒数、戻る回数、外部検索の有無 |
| Installation | 選んだ方法、実行コマンド、エラー、`import gwexpy`の成否と秒数、介入回数 |
| Quickstart | `asd.png`の成否と秒数、再実行の成否、optional packageの要求、介入回数 |
| 理解 | ASDの軸、ピーク、ビン幅、ピーク高さに関する四問の正誤 |
| 経験者課題 | 成果物または概念対応の成否、所要秒数、介入回数 |
| 主観 | 迷った場所、次に読みたいページ、信頼度、5段階の容易さ評価 |
| 分類 | Docsの問題、環境の問題、両方、未確定のいずれかと根拠 |

完了率だけでなく、所要時間の中央値、誤った経路、戻る操作、介入回数、外部検索を報告する。
参加者4名の結果から一般化した統計的主張は行わない。

ベースラインの判定基準は次のとおりとする。

- 4名中3名以上が30秒以内に妥当な入口を選ぶ。
- Python環境が利用可能になった後、4名中3名以上が10分以内に`import gwexpy`を成功させる。
- 4名全員がoptional packageなしで15分以内に`asd.png`を保存する。
- 4名中3名以上が四つの理解確認項目を正しく説明する。
- P03とP04が、各自の追加課題を1回以下の介入で完了する。

1名でも共通課題を完了できなければBlockerとする。
同じ摩擦が2名以上に現れればP1候補とする。
入口選択の遅延、トップとStart Hereの重複、Experimentalistのanchorへの着地はMajorとして分類する。
Installationの語彙、版バナー、タイトル、テーマ由来の英語は、完了を妨げる証拠がある場合だけP2またはP3として扱う。

Pythonの導入、ネットワーク、パッケージインデックスなどの環境固有の失敗は、Docsの失敗と分けて記録する。
原因を確認できない場合は「未確定」と記録し、Docsの修正根拠にはしない。

## 成果物と後続判断

試験実施後、匿名化した集計結果を`docs/developers/reports/`配下の日時付きMarkdown報告書にまとめる。
報告書には、参加者背景、言語、環境条件、タスク別完了率、時間の中央値、介入回数、代表的な詰まり、Docs問題と環境問題の分類を含める。
個別の録画、音声、生ログはリポジトリに追加せず、同意範囲に応じたローカル保管とする。

トップとStart Hereの重複が試験で確認された場合の既定の後続案は、トップを背景選択に保ち、Start Hereを「環境準備、最初の解析、次の一歩」の線形案内に変えることである。
Experimentalist用wrapper、Installationの分割、Commissionerの表示タイトル変更は、対応する摩擦が試験で確認されたものだけを次の小規模PRに含める。

後続PRで公開Docsを変更する場合は、英語ソースと日本語gettextを同時に更新し、既存URLとanchorを維持する。
厳格な英日Docs build、linkcheck、日英構造検証、`check_public_docs.py`による公開SHA、6入口、PNG、PythonおよびXML配布物の読み戻しを実施する。
Notebookを変更した場合は、既存のNotebook実行ポリシーに従い、変更範囲の実行結果を別に記録する。
