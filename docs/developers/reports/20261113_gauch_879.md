## Direct comparison with the uploaded original functions

Both settings use the same seeded white-Gaussian time series at 4096 Hz, with
amplitude scale 1e-21, periodic Hann windows, segment mean removal, 50% overlap,
and 39 ASD samples. Original `spectrogram4`, `my_kstest`, and `kstests` are executed
from the supplied source. ASD comparison includes every frequency; the KS and
operational comparison use the original [10, 1500) Hz slice.

| Interval / FFT | ASD maximum absolute difference | Fitted-scale maximum relative-to-peak error | KS maximum absolute difference | Threshold decision mismatches |
|---|---:|---:|---:|---:|
| 120 s / 6 s | 0 | 2.80e-16 | 3.33e-16 | 0 |
| 20 s / 1 s | 0 | 2.78e-16 | 3.33e-16 | 0 |

The product statistic map also matches these original statistics at rtol=1e-12,
with no absolute tolerance. The product p-value map is separately checked against
its own seeded simulated null and `(r+1)/(N+1)` helper.

The original driver is not launched as a cluster CLI. Its actual AST statements at
lines 239-249, from `ref = ks_map.value` through the threshold/encoding assignments,
are executed with controlled synthetic inputs. Original `kstests()` returns KS
statistics; the driver loads `n39.npy`, obtains the 5% threshold
0.16902473151769043, and encodes decisions as 0.025 / 1 (or -1 for an excluded
interval). This driver block agrees with the corresponding GWexpy-statistic
threshold decisions. Those encodings are **not numerical p-values**. The synthetic
reference inputs have no excluded intervals; dead-bin NaN behavior has separate
product regression tests.

For the numerical-p-value path, original `ksstatic_to_pv()` and the new rank helper
are evaluated on the **same** n39 reference array. Maximum differences are
9.995e-5 and 9.993e-5, respectively. This isolates the finite-rank formula change;
it is not a claim that independently generated null arrays return identical p-values.

Original n39 quantiles (50%, 95%, 99%) are 0.1090354238, 0.1690104424,
0.2007013096. A seeded 20,000-trial product null gives 0.1090472328,
0.1696155322, 0.2004950125. Their two-sample KS distance is 0.00895.
These are stochastic distribution comparisons, not numerical-identity assertions.

## Production-statistic null comparison

The experiment uses 20,000 independent time-series windows to generate each FFT
null and another 20,000 independent windows to evaluate it. It uses the actual
product ASD and KS helpers, checks their result against `compute_gauch()` on a
complete first window, and uses the product rank-p-value helper. The independent
amplitude null uses the product generators with scale refitted in every trial.

Settings match the earlier standalone benchmark: 256 Hz, 1 s Hann FFT, constant
detrending; no overlap/n=40 and 50% overlap/n=39. These calibration experiments
are distinct from the 4096 Hz original-function comparison above. They do not
claim exhaustive calibration over all sample rates or FFT lengths.

| Overlap | Bin class | Independent-null P(p<=.05) | FFT-null P(p<=.05) | Independent-null P(p<=.01) | FFT-null P(p<=.01) |
|---|---|---:|---:|---:|---:|
| 0% | Interior pooled | .052560 | .049832 | .010361 | .010005 |
| 0% | DC | .046050 | .049450 | .008700 | .009750 |
| 0% | Nyquist | .047550 | .048000 | .010000 | .011200 |
| 50% | Interior pooled | .050914 | .049665 | .010459 | .009910 |
| 50% | DC | .052700 | .051400 | .011800 | .010850 |
| 50% | Nyquist | .047650 | .055300 | .010900 | .013150 |

The JSON retains first/second interior bins separately, per-group rates and their
mean/median/SD/SE. Evaluation windows are split into 40 independent groups of 500;
frequency bins within a window are not treated as independent observations for
those errors. The paired group SE conditions on the generated null and **does not
include its common Monte Carlo error**.

Four disjoint 5,000-trial null blocks provide a rough separate null-error estimate
(block-rate SD / sqrt(4)); this is a diagnostic with only four blocks, not a
precision guarantee. At 50% Nyquist the independent-minus-FFT rate difference is
-0.00765, paired evaluation SE 0.000675, and separate null SE estimates are
0.000805 (independent) and 0.002158 (FFT). The difference must not be judged using
the evaluation SE alone. Correlation and finite-null variation both remain
possible contributors; these results do not establish equivalence.

**Scientific decision requested:** assess this bin-specific comparison and its
uncertainty before accepting the independent amplitude null. If materially
inaccurate, prefer a scoped overlap-aware calibration under #879. No such null
redesign or automatic scientific approval is introduced by this evidence update.

## Product before/after and the short-FFT defect

[The supplemental results](20261113_gauch_879_supplement.json) compare the actual
main implementation, loaded from the exact baseline source SHA above, with the
integrated product on identical inputs. Four realizations of 1024 s at 64 Hz,
FFT=1 s, n=40, disjoint testing windows, N=5000 give mean interior rejection rates:

| Product | P(p<=.05) | P(p<=.01) |
|---|---:|---:|
| main before #879 | .581290 | .301935 |
| integrated #879 | .043548 | .009677 |

This is a new, small descriptive product-code experiment. It is not the historical
40-realization/20,000-trial standalone benchmark reported in the initial PR.
The individual realizations and statistic/p-value medians are retained in JSON.

A focused diagnostic found an accepted three-sample FFT has a non-Rayleigh
interior amplitude after Hann windowing and mean removal. On 5000 independent
Gaussian windows, n=39, its unguarded 5% rejection rates were .3016, .3252 and
.3314 for hops 1, 2 and 3. The failure persists for disjoint segments, so it
cannot be attributed solely to overlap. The product now rejects nfft=3 explicitly
with `ValueError`; public-path tests cover all three hops. This is an intentional
exception change requiring the same human scientific review as the rest of #879.
No new public parameter or default was introduced; other odd FFT lengths retain
the existing nearest-half-hop behavior.

The following supplemental experiment was executed with
`PYTHONPATH=. memcap -- conda run --no-capture-output -n gwexpy python <script>`.
It reproduces the numerical supplement without access to KAGRA data:

```python
import json, os, subprocess, types
from pathlib import Path
import numpy as np
from gwexpy.timeseries import TimeSeries
from gwexpy.statistics.gauch import _segment_asds, _ks_statistic, _get_lilliefors_null_distribution, compute_gauch
from gwexpy.statistics._monte_carlo import upper_tail_rank_pvalue
base=subprocess.check_output(['git','rev-parse','origin/main'],text=True).strip()
source=subprocess.check_output(['git','show',base+':gwexpy/statistics/gauch.py'],text=True)
old=types.ModuleType('gwexpy.statistics._gauch_baseline')
old.__package__='gwexpy.statistics'
exec(compile(source,'gauch_baseline.py','exec'),old.__dict__)
beforeafter=[]
for seed in range(4):
 ts=TimeSeries(np.random.default_rng(8790+seed).normal(size=1024*64),sample_rate=64)
 a=old.compute_gauch(ts,fftlength=1,window=40,n_monte_carlo=5000,seed=100+seed)
 b=compute_gauch(ts,fftlength=1,window=40,n_monte_carlo=5000,seed=100+seed)
 row={'seed':8790+seed}
 for name,r in [('before',a),('after',b)]:
  p=r.pvalue_map.value[::40,1:-1]
  row[name]={'rate005':float(np.mean(p<=.05)),'rate001':float(np.mean(p<=.01)),'median_p':float(np.median(p)),'median_statistic':float(np.median(r.statistic_map.value[:,1:-1]))}
 beforeafter.append(row)
null=_get_lilliefors_null_distribution(39,20000,seed=879)
short=[]
for hop in [1,2,3]:
 rng=np.random.default_rng(879)
 ds=[]
 for i in range(5000):
  asd=_segment_asds(rng.normal(size=3+38*hop),3,3,hop)
  ds.append(_ks_statistic(asd,np.array([True,False]))[1])
 p=upper_tail_rank_pvalue(null,np.array(ds))
 short.append({'nfft':3,'hop':hop,'independent_windows':5000,'rate005_without_guard':float(np.mean(p<=.05))})
result={'baseline_sha':base,'before_after':beforeafter,'nfft3_diagnostic':short,'classification':'Observed. Four-realization product comparison is descriptive, not the 40-realization historical experiment.'}
Path(os.environ['TMPDIR']+'/gauch879-supplement.json').write_text(json.dumps(result,indent=2)+'\n')
print(json.dumps(result),flush=True)

```
