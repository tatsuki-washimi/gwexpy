`AUDIO-METADATA-001` is confined to the optional `extract_metadata=True` public registry path tested with explicit `format="flac"` and `format="wav"` on `TimeSeriesDict.read`; the auto-identified metadata option was not separately exercised. The public contract's missing-tinytag warning-and-skip rule applies to the `base` environment, not the installed-tinytag case. The public WAV reader docstring at `gwexpy/timeseries/io/wav.py:56-60` and compressed-audio reader docstring at `gwexpy/timeseries/io/audio.py:104-108` both say available metadata is stored in provenance. The registry path supplies a `FileIO` object; the direct reader receives a filesystem path. `extract_audio_metadata` handles the latter. The tagged FLAC title provides decisive metadata-loss evidence; WAV's available bitrate/duration and false warning support the shared route mechanism. No sample or timing corruption was observed.

## Fixture authority and dependency behavior

- `OBSPY-DUP-001`: `d_lane.py` writes two miniSEED files per variant using native ObsPy `Trace.write`; native `obspy.read` plus `Stream.merge(method=1, fill_value=nan)` provides the expected merged values. The public path uses actual `TimeSeriesDict.read`; an instrumented `Stream.merge` records pre/post trace IDs, rates, dtypes and lengths. Gap result `[1,2,3,4,nan,nan,5,6,7,8]`; overlap result `[1,2,50,60,70,80]`. Public `float64` conversion is visible and necessary for `nan` padding. `base` has no ObsPy, so this case is `BLOCKED` there with reason `NO_DEPENDENCY`; `present` resolves it.
- `SDB-KW-001`: SQLite `archive(dateTime INTEGER, outTemp REAL, outHumidity REAL)` rows at Unix times 1700000000/1700000300/1700000600. Astropy `Time(..., format="unix").gps` is the independent time expectation. Direct/public reads return `outTemp` °C `[21.11111111111111,21.666666666666668,22.22222222222222]` and `outHumidity` percent `[50,51,52]`, each shape `(3,)`, `float64`, 300 s cadence.
- `WIN-KW-001`: source bytes `00000013240102030405000110020000000a01` encode 2024-01-02 03:04:05, channel 0001, 2 Hz, absolute 10 then +1 delta. Contract/source WIN packet rules are the format authority. In `base`, direct and explicit registry reads raise `ImportError: obspy is required to read WIN format files`; auto-identification raises `IORegistryError` because WIN is conditionally unregistered, as allowed by the contract. No dependency block in `present`.
- `WAV-CONTROL-001`: `scipy.io.wavfile.write` writes the five-frame asymmetric stereo `int16` fixture; `scipy.io.wavfile.read` is the native sample/timing oracle. In `base`, WAV data reads succeed.
- `AUDIO-CONTROL-001`: pydub exports the WAV fixture to lossless FLAC with title `D audit title`; native pydub provides the sample/timing oracle. In `base`, explicit/auto public FLAC reads raise the documented pydub `ImportError`. Other compressed codecs (MP3/OGG/M4A) were not exercised.
- `AUDIO-METADATA-001`: native tinytag on the tagged FLAC yields `{'title': 'D audit title', 'bitrate': 281.6, 'duration': 0.000625}`. Direct `read_timeseriesdict_audio(flac_path, format_hint="flac", extract_metadata=True)` returns those fields in `_gwexpy_io`; public explicit-format `TimeSeriesDict.read` yields `_gwexpy_io=None` and a file-not-found warning. Direct WAV reader likewise has bitrate/duration provenance without a warning, while public explicit-format WAV read has neither. The direct/public data summaries are equal. In `base`, WAV `extract_metadata=True` warns and skips because tinytag is absent, matching the contract; compressed-audio read stops first at the pydub `ImportError`.
