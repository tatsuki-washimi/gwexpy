| TDMS-TIME-008 | `CONFIRMED_CORRECTNESS_DEFECT` | `BLOCKED` (`AMBIGUOUS_CONTRACT`) | With `wf_increment=0.25`, no `wf_start_time`, and no root `DateTime`, `TimeSeries.read(..., format="tdms")` returns `t0=0`, `dt=0.25`, and coordinates `[0, 0.25, 0.5]`. npTDMS `time_track()` returns the same *relative* coordinates. Using actual data size`. This is plainly an implemented salvage branch, but no Metronix ATS format authority or published GWexpy contract found that requires or endorses partial recovery. Do not infer normative intent from the branch alone. |
| GBD-COUNT-001 | `CONFIRMED_CORRECTNESS_DEFECT` | `BLOCKED` (`AMBIGUOUS_CONTRACT`) for malformed GL500 input | Header `Counts=2` with three complete rows gives two rows without warning. The Graphtec-authored GL500 sheet defines `Counts` as number of data points, data region end as end-of-file, and data byte length from channel count × Counts × 2. Thus an extra row is **not valid under that GL500 specification**; there is no supported third sample to claim was lost from a valid file. The public GWexpy GBD contract does not specify whether malformed surplus bytes must error, warn, or be ignored. The implementation's behavior is established, while correctness classification needs a malformed-input policy. Do not generalize to other Graphtec models. |

## Authority boundaries

- TDMS public contract: `docs/developers/contracts/public_io_contract.json` entry `tdms` (`time_semantics: absolute`, `epoch_arg: override`, metadata rule for waveform timing), and `docs/developers/contracts/public_io_contract.md` lines 42–49, 114, 252–258. Public reader docstring: `gwexpy/timeseries/io/tdms.py` lines 62–67. Native rule: [NI TDMS File Format, “Predefined Properties”](https://www.ni.com/en/support/documentation/supplemental/07/tdms-file-format-internal-structure.html#predefined-properties) defines `wf_start_time` as possibly zero for relative/non-time data and `wf_increment` as axis spacing; [npTDMS 1.11.0 reading documentation](https://nptdms.readthedocs.io/en/stable/reading.html) describes relative `time_track()` and optional absolute time. GWexpy's audio documentation explicitly describes `t0=0` as a convenience origin (`docs_redesign/reference/io_capabilities.md` line 310), but does not extend that convention to TDMS.
- ATS public contract: `docs/developers/contracts/public_io_contract.md` lines 296–302 and JSON entry `ats`; neither defines truncation behavior. [Metronix MTHotel README, “ATSS” and “Naming Convention”](https://github.com/bfrmtx/MTHotel#atss) distinguishes old header-bearing `.ats` from stream-like `.atss`; its file-size rule applies to `.atss` only. [Resistics ATS reader source, `_set_n_samples` and `read_data`](https://resistics-readers.readthedocs.io/en/stable/_modules/resistics_readers/metronix/ats.html) reconciles XML timestamp and channel metadata counts, then reads the declared range with `np.memmap`; it does not establish a binary-header-versus-payload salvage rule. [Metronix ATS header table reproduced in a Québec geophysical survey, Appendix 3 p. 30](https://gq.mines.gouv.qc.ca/documents/EXAMINE/GM60694/GM60694.pdf) identifies the header sample-count field, but does not prescribe truncation handling.
- GBD public contract: `docs/developers/contracts/public_io_contract.md` lines 244–250 and JSON entry `gbd`; it specifies public read routes and required timezone, not surplus-payload policy. The [Graphtec-authored GL500 Binary Data File Format Specification Sheet, §§1.2 and 2.3.2](https://studylib.net/doc/8138865/gl500-binary-data-file-format-specification-sheet) states the data region ends at EOF, `Counts` is the number of captured points, and the byte-count equation. **This is a Studylib mirror of a manufacturer-authored document, not a Graphtec-hosted copy.** [Graphtec's own GBD FAQ](https://www.graphteccorp.com/logger_qa/qaqr_gl_029/) confirms GBD is its instrument binary format but does not publish `Counts`, payload layout, or mismatch policy. Other model variants therefore remain `BLOCKED` (`NO_FORMAT_AUTHORITY`).
