This patch fixes supported NetCDF4 and Zarr matrix value, axis, and unit
handling; HDF5 manifest integrity; TDMS waveform-increment and GBD header
validation; and audio registry tag provenance. The supported optional-backend
routes report a backend-specific `ImportError` when their package is absent.
The new candidate also targets internal I/O performance and scalability under
#580. Its release date is TBD; implementation and qualification remain pending.
It adds no public API, dependency, or persistence schema.

### Fixed

- **NetCDF4 matrices and axes**: Reject malformed matrix topology, unsafe heterogeneous dtype conversion, and irregular legacy time axes; retain cell units in supported matrix writes and legacy reads.
- **Zarr values and metadata**: Retain tested integer and complex samples, axes, and units; reject unsafe mixed-dtype conversion and inconsistent axes in supported stores.
- **HDF5 manifest-backed collections**: Reject unreadable, missing, or substituted payloads while preserving tolerant manifest-free discovery.
- **TDMS and GL500 GBD validation**: Reject absent or invalid waveform increments and malformed required GL500 header fields within the tested firmware scope.
- **Audio registry tags**: Retain available WAV and FLAC tag metadata in provenance.
- **Optional backends**: Supported public Zarr and NetCDF4 routes raise a backend-specific `ImportError` when the required package is absent.

### Planned performance scope

- **Measurement and I/O paths (#581–#585, #588–#589)**: Freeze old-candidate baselines before improving multi-file merge, single-channel dispatch, range reads, CSV/SDB/TDMS, native DTTXML parsing, and GWF merge scalability.
- **WIN and copies (#518, #586)**: Include only NumPy-based WIN decoding and dtype-preserving copy reduction. Numba and the remaining #518/#586 work are deferred. #587, #590, and #519 are excluded.
- **Native DTTXML skipped-payload exception (#589)**: Already accepted selectors may let the native parser skip warnings and decode errors arising exclusively from fully unselected payloads. XML structural errors and selected-payload behavior must match the old candidate. The external `dttxml` route keeps its existing behavior and is outside the performance claim. Separate human scientific/data-model approval is required for this exception. It does not extend #611's exception for completely disjoint plain HDF5 read windows.
- **SDB concurrent-write snapshot correction (#585)**: The proposed reader validates and fetches selected rows within one SQLite snapshot. A concurrent valid selected-payload update may no longer appear in that read when schema, time, unit, and validation inputs are unchanged. Other concurrent changes remain HOLD pending separate review. This scoped difference needs human scientific/data-model approval; ordinary values, warnings, and errors remain subject to the old-R contract.

Except for these scoped exceptions, the performance work must preserve public
numerical results, dtype, metadata, warnings, errors, and on-disk format. The
2026-09-27 S/R approvals are historical; S2 needs new reviews and approval,
and R2 needs exact-artifact qualification before release GO.
