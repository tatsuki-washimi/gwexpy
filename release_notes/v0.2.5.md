This patch fixes supported NetCDF4 and Zarr matrix value, axis, and unit
handling; HDF5 manifest integrity; TDMS waveform-increment and GBD header
validation; and audio registry tag provenance. The supported optional-backend
routes report a backend-specific `ImportError` when their package is absent.
The new candidate also targets internal I/O performance and scalability under
#580. Its release date is TBD; implementation and qualification remain pending.
It adds no public API, dependency, or persistence schema.

### Fixed

- **NetCDF4 matrices and axes**: Reject malformed matrix topology, unsafe heterogeneous dtype conversion, and irregular legacy time axes; retain cell units in supported matrix writes and legacy reads.
- **Zarr values and metadata**: Retain tested integer and complex samples, axes, and units; reject unsafe mixed-dtype conversion and inconsistent axes in supported stores.
- **HDF5 manifest-backed collections**: Reject unreadable, missing, or substituted payloads while preserving tolerant manifest-free discovery.
- **TDMS and GL500 GBD validation**: Reject absent or invalid waveform increments and malformed required GL500 header fields within the tested firmware scope.
- **Audio registry tags**: Retain available WAV and FLAC tag metadata in provenance.
- **Optional backends**: Supported public Zarr and NetCDF4 routes raise a backend-specific `ImportError` when the required package is absent.

### Internal performance work (release qualification pending)

- **Multi-file merge and WAV dispatch (#582–#583)**: The measured 64-input merge appends each input once, and selected-channel WAV reads no longer construct an unselected `TimeSeries`. Public result fingerprints match the frozen baseline. The WAV backend still reads the full interleaved payload; the merge has no peak-memory improvement claim.
- **CSV reader and writer (#585)**: General numeric parsing and selected-column reads use less work, and CSV writes stream output. The measured general and selected CSV fixtures improve in wall time. Explicit-format and `.csv` auto-detected two-column `FrequencySeries` reads retain their fast paths and nonuniform frequency axes; fixed-encoding/newline writer fixtures retain byte identity.
- **WIN decoding (#518)**: NumPy integer intermediates preserve bit-exact output and remove measured per-sample append work; warm CPU improves on the frozen fixture.
- **Native DTTXML PSD selection (#589)**: Large native PSD reads skip decoding fully unselected payloads. The measured fixture decodes zero unselected bytes and reduces Linux peak PSS by 19.63%; small files retain the old parser. Large warm wall time increases 12.46% on the same fixture, while cold time is comparable. The scoped warning exception below still requires human approval.
- **Serial GWF merge (#588)**: Large, sorted, local serial reads retain at most three coerced parts regardless of frame count. The measured 64 MiB fixture reduces Linux peak tree PSS by 8.31–10.66% in independent batches; large warm time improves 4.20%. The parallel route remains separately unqualified.
- **Pending lanes (#585 SDB, #588 parallel, #586)**: Finish the SDB and parallel GWF evaluations, then audit remaining copies. TDMS unselected reads were already optimized in the old-candidate baseline.
- **Range push-down (#584)**: The baseline found errors from corrupt chunks outside requested windows in HDF5, NDScope, NetCDF4, and Zarr. This optimization is on hold because skipping those chunks would change the current error behavior; no #584 reader change is included.
- **WIN and copies (#518, #586)**: Include only NumPy-based WIN decoding and dtype-preserving copy reduction. Numba and the remaining #518/#586 work are deferred. #587, #590, and #519 are excluded.
- **Native DTTXML skipped-payload exception (#589)**: Already accepted selectors may let the native parser skip warnings and decode errors arising exclusively from fully unselected payloads. XML structural errors and selected-payload behavior must match the old candidate. The external `dttxml` route keeps its existing behavior and is outside the performance claim. Separate human scientific/data-model approval is required for this exception. It does not extend #611's exception for completely disjoint plain HDF5 read windows.
- **SDB concurrent-write snapshot correction (#585)**: The proposed reader validates and fetches selected rows within one SQLite snapshot. A WAL commit during that read can change values, warnings, or errors compared with old R's mixed snapshots. A frozen fault matrix will characterize payload, timestamp, `usUnits`, schema, and malformed-value updates before implementation. The exact concurrent scope requires separate review and human scientific/data-model approval; static-source behavior remains subject to the old-R contract.

Except for these scoped exceptions, the performance work must preserve public
numerical results, dtype, metadata, warnings, errors, and on-disk format. The
2026-09-27 S/R approvals are historical; S2 needs new reviews and approval,
and R2 needs exact-artifact qualification before release GO.
