This patch fixes supported NetCDF4 and Zarr matrix value, axis, and unit
handling; HDF5 manifest integrity; TDMS waveform-increment and GBD header
validation; and audio registry tag provenance. The supported optional-backend
routes report a backend-specific `ImportError` when their package is absent.
The current candidate base also covers internal I/O performance and
scalability under #580. The release date is 2026-10-04 UTC. The #584 overlay
and optional parallel #588 patch are deferred; the R8 serial #588 implementation
is retained unchanged. Final-source review and release qualification remain
pending. See the current v0.2.5 release plan for the independent four-case
decision and its evidence limits. The candidate adds no
public API, dependency, or persistence schema.

### Fixed

- **NetCDF4 matrices and axes**: Reject malformed matrix topology, unsafe heterogeneous dtype conversion, and irregular legacy time axes; retain cell units in supported matrix writes and legacy reads.
- **Zarr values and metadata**: Retain tested integer and complex samples, axes, and units; reject unsafe mixed-dtype conversion and inconsistent axes in supported stores.
- **HDF5 manifest-backed collections**: Reject unreadable, missing, or substituted payloads while preserving tolerant manifest-free discovery.
- **TDMS and GL500 GBD validation**: Reject absent or invalid waveform increments and malformed required GL500 header fields within the tested firmware scope.
- **Audio registry tags**: Retain available WAV and FLAC tag metadata in provenance.
- **Optional backends**: Supported public Zarr and NetCDF4 routes raise a backend-specific `ImportError` when the required package is absent.

### Internal performance work (release qualification pending)

- **Multi-file merge and WAV dispatch (#582–#583)**: The measured 64-input merge appends each input once, and selected-channel WAV reads no longer construct an unselected `TimeSeries`. Public result fingerprints match the frozen baseline. The WAV backend still reads the full interleaved payload; the merge has no peak-memory improvement claim.
- **CSV reader and internal writer (#585)**: General numeric parsing and selected-column reads use less work. The internal enhanced `write_timeseries_csv` helper streams output; public `TimeSeries.write(format="csv")` uses GWpy's writer and is outside this writer performance claim. The measured general and selected CSV fixtures improve in wall time. Explicit-format and `.csv` auto-detected two-column `FrequencySeries` reads retain their fast paths and nonuniform frequency axes; fixed-encoding/newline internal-writer fixtures retain byte identity.
- **WIN decoding (#518)**: NumPy integer intermediates preserve bit-exact output and remove measured per-sample append work; warm CPU improves on the frozen fixture.
- **Native DTTXML PSD selection (#589)**: Large native PSD reads skip decoding fully unselected payloads. The measured fixture decodes zero unselected bytes and reduces Linux peak PSS by 19.63%; small files retain the old parser. Large warm wall time increases 12.46% on the same fixture, while cold time is comparable. The scoped warning exception below still requires human approval.
- **GWF scalability (#588)**: Retain the R8 serial optimization. The optional parallel patch is deferred because its broad structural and valid process-tree PSS inclusion gates remain unmet. Earlier measurements and the single spawn-import diagnostic do not qualify the final source.
- **SDB selected windows (#585)**: For an eligible 4,096-row SQLite source, the reader validates the full source in one read transaction while materializing only the 512 requested payload rows into a DataFrame. Static-source values, metadata, warnings, and errors match old R. The two small selected-read timing batches are inconclusive under the frozen noise-aware gate; no wall-time or PSS improvement is claimed. TDMS unselected reads were already optimized in the old-candidate baseline.
- **Dtype-preserving copy reduction (#586)**: The frozen B-X comparison (baseline freeze commit `836e6f38`, candidate source `913ab6c77`, evidence commit `26ae634`, and append-only gate correction `bf258`) matches all 11/11 public fingerprints, with no dtype, value, or warning change. Audited source-site full-payload `ndarray.astype` calls fall from 1 to 0 for ATS32 and ATS64, and from 32 to 0 for the 16-cell NetCDF matrix. NetCDF warm wall and CPU medians improve 33.23% on the measured fixture; ATS wall/CPU and all PSS results remain evidence-only. Three supplementary small-input cases pass the non-regression check. Release qualification remains pending. Evidence: `docs/developers/reports/v0.2.5-performance/X/dade6bd54082ef7f771724b84064caeb252342317e0da5cdc81a966f5e916050/candidate-v1-913ab6c/README.md` and sibling `candidate-v1-913ab6c-interpretation-v2/README.md`.
- **Range push-down (#584)**: The nine-path candidate-A overlay is deferred. Its primary performance gate remains unmet, and the new full 72-command campaign was not launched. Accepted physical-fetch and scoped remote Zarr results do not replace that gate.
- **WIN and copies (#518, #586)**: Include only NumPy-based WIN decoding and dtype-preserving copy reduction. Numba and the remaining #518/#586 work are deferred. #587, #590, and #519 are excluded.
- **Native DTTXML skipped-payload exception (#589)**: The proposed exception is limited to warnings and decode errors arising exclusively from fully unselected native-parser payloads after an accepted selector is applied. XML structural errors and selected-payload behavior retain the reviewed baseline contract. The external `dttxml` route is unchanged. Fresh human scientific/data-model approval bound to final `S` is required. This does not extend #611's exception for completely disjoint plain HDF5 read windows.
- **SDB concurrent-write snapshot correction (#585)**: The proposed exception is limited to differences caused when a WAL writer commits after the reader pins one SQLite snapshot for validation and payload retrieval. It requires fresh human scientific/data-model approval bound to final `S`. The canonical release plan retains the historical matrix and required evidence; this note does not claim final-source qualification.

### Retained I/O limits under historical audit review

- **TDMS timing and units**: Without a channel start timestamp, the current reader uses a custom root `DateTime` as an assumed UTC epoch or relative `t0=0` when neither exists. A root `DateTime` is not guaranteed to be the channel acquisition time. Pass `epoch=` when its authority matters. Channel `unit_string` is not imported automatically; pass `unit=` when known. The legacy provenance marker `unit_source=tdms` does not certify unit import.
- **HDF5 histogram collection layout**: `layout="dataset"` currently writes physical entry groups while the manifest labels them `dataset-per-entry`. The physical dataset-per-entry histogram schema is not qualified. Existing written files retain their current layout.
- **Other retained malformed-input behavior**: GBD uses the declared `Counts` and silently ignores surplus complete rows; ATS can return a truncated payload with a warning. These are existing behaviors for malformed files, subject to the twelve-case scientific disposition review. Native Zarr int16, int32, and float32 stores may read back as float64 with exact values.
