# GWexpy v0.2.10

This consolidated maintenance release addresses scientific-data integrity in numerical statistics, physical units, time/frequency coordinates, HDF5 and collection I/O, diagnostic visibility, and compatible GWpy 4.x behavior, within the existing public API.

## Main corrections

- **GauCh (#879, PRs #900/#905):** use single-FFT ASD samples, the standard two-sided KS statistic, finite-rank Monte Carlo p-values and frequency-bin-specific nulls; preserve KAGRA original numerical agreement on the tested even-FFT settings. The odd-length final bin uses a matched Gaussian FFT-process null. DC/Nyquist overlap calibration and the `nfft=3` error contract were scientifically accepted.
- **Monte Carlo Rayleigh test (#507, PR #898):** correct two-sided finite-sample rank p-values; preserve seeds, RNG and null-statistic behavior.
- **HDF5 coordinates (#881/#882/#883/#887):** retain irregular and near-regular time/frequency axis values, including when GWpy's regularity tolerance would silently linearize them; preserve SpectrogramMatrix frequency axes.
- **Lossless metadata and physical units (#771/#773/#774/#776/#777):** expose unreadable collection members, reject incompatible error-bar units and invalid unit metadata, and avoid silently omitting unencodable attributes.
- **Additional corrections:** spatial FFT coordinate origin/direction (#544), Welch overlap standard errors (#772), I/O error propagation (#775), statistics warning call sites and input guard (#513), and time CLI GWpy compatibility (#784).

The exact set of adopted behavior changes, limitations and before/after contracts is documented in [CHANGELOG.md](../CHANGELOG.md). Existing APIs, dependencies and supported persistence schemas are preserved; some invalid inputs now fail explicitly instead of producing misleading results.

**Install after release:** `pip install gwexpy==0.2.10`

**Status:** prepared release notes; publication requires the existing Source Approval, Candidate Qualification and Release GO process.
