# GWexpy v0.2.9

This maintenance release corrects four unit and GWpy compatibility issues within the existing public API and supported dependency range.

### Fixed

- **Matrix phase values and units (#770):** `TimeSeriesMatrix.radian()` and `.degree()` return real floating-point phase values, avoiding integer truncation and a spurious complex result dtype. The matrix, `meta.units`, and each element's `TimeSeries.unit` match the returned `rad` or `deg`; the source matrix is unchanged.
- **HDF5 frequency units (#774):** Every nonempty `frequency_unit` is parsed and must be frequency-equivalent to Hz, including when frequencies are derived from `df`/`f0` or left implicit. Malformed or dimensionally incompatible units raise instead of silently labeling the axis as Hz. Valid units such as kHz still convert the axis, and an absent attribute keeps the existing fallback.
- **Inverse whitening units (#778):** `WhitenTransform.fit()` records input feature units and `inverse_transform()` restores them in feature order, including reduced-component reconstruction. The whitening calculation is unchanged.
- **GWpy 4.x proxy imports (#866):** `gwexpy.detector.channel` and `gwexpy.plot.gps` import successfully with GWpy 4.1.0 while retaining curated public re-exports. The GWpy 4.0.x compatibility path is covered by the release matrix.

### Intentional behavior changes

- Matrix phase results are real floating-point values, with matrix and per-element units matching the radians or degrees returned.
- Invalid nonempty HDF5 frequency-unit metadata fails closed, even when the axis has no explicit samples.
- Inverse-whitening results now expose the fit-time physical units instead of dimensionless units.
- Imports through the two GWpy proxy modules no longer expose removed, unused GWpy internals; curated public re-exports remain available.
