This maintenance release clarifies documentation contracts, refines diagnostic
warning messages, and completes repository cleanup following the decoupling of the
legacy in-tree GUI to the independent `pyaggui` project. It introduces no new
public APIs, dependencies, or storage formats. Tested scientific values, dtypes,
axes, and units are preserved.

### Fixed

- **ASD frequency-grid rejection diagnostics**: Distinguish rejection causes
  when validating frequency grids in ASD response functions, emitting specific
  informative warnings while preserving warning categories and stack levels (#790, PR #794).

### Documentation

- **`TimeSeries.spectrogram2()`**: Document the non-averaged periodogram execution
  path and state that extra keyword arguments are forwarded to
  `scipy.signal.periodogram`, where `method=` is rejected (#779, PR #798).
- **`TimeSeriesDict.append()`**: Document in-place dictionary update behavior and
  explicit `self` return contract (#640, PR #798).
- **GUI transition guide**: Update English and Japanese user guides and how-to
  documentation to point to the independent `pyaggui` and `GWexpy Studio`
  projects (#645, PR #803).

### Removed

- **Legacy in-tree GUI**: Fully removed deprecated `gwexpy/gui/` implementation
  and associated `tests/gui/` tests, GUI-specific development dependencies, packaging
  exclusions, and CI fixtures following ADR 0001 (#645, PR #802, PR #803).
  Boundary defense tests added to prevent accidental reintroduction.
- **Obsolete NDS live workflow**: Removed the manual `nds-live.yml` workflow,
  which selected no tests after the GUI cleanup. NDS library I/O and offline
  analysis support are retained; no replacement live workflow is provided.

### Known limitations

The following issues remain unresolved in v0.2.6. No workaround has been
verified for these cases; treat affected outputs and files with the cautions
below. Each issue is an individual patch candidate for v0.2.7 or a later
version, with no commitment that it will be included in v0.2.7.

- **[#766 — missing GWF files with `framel`](https://github.com/tatsuki-washimi/gwexpy/issues/766)**: A `TimeSeriesDict`/GWpy GWF read of a path that does not exist can reach the native `framel` reader with `backend="framel"` or `backend=None` and terminate the process with a segmentation fault. This is a process-crash risk; v0.2.6 does not fix it, and no safe workaround has been verified.
- **[#767 — `PercentileThreshold.threshold()` units](https://github.com/tatsuki-washimi/gwexpy/issues/767)**: When PSD inputs with incompatible units reach `bkg_table`, the threshold calculation can continue on raw magnitudes after warning. The resulting threshold may not have a valid physical interpretation. Do not rely on such a result; v0.2.6 does not fix it, and no safe workaround has been verified.
- **[#768 — `standardize_matrix` units](https://github.com/tatsuki-washimi/gwexpy/issues/768)**: After z-score standardization, the matrix and its elements can retain the original physical units even though the values are dimensionless. Unit-aware downstream code may therefore misinterpret results. v0.2.6 does not fix this, and no workaround has been verified.
- **[#769 — `StandardizeTransform` units and method fallback](https://github.com/tatsuki-washimi/gwexpy/issues/769)**: The transform can retain physical-unit metadata on standardized values, and an unrecognized method can silently fall back to z-score. This can produce misleading unit metadata or an unintended transform. v0.2.6 does not fix either behavior, and no workaround has been verified.
- **[#770 — `TimeSeriesMatrix.radian()` / `.degree()` units](https://github.com/tatsuki-washimi/gwexpy/issues/770)**: The values are converted, but container and element unit metadata can remain inconsistent with the angular values. Consumers inspecting units may infer the wrong quantity. v0.2.6 does not fix this, and no workaround has been verified.
- **[#771 — non-manifest HDF5 collection reads](https://github.com/tatsuki-washimi/gwexpy/issues/771)**: When an entry in a non-manifest HDF5 collection fails to read, some collection readers can silently skip it and return a partial or empty collection. The returned data may be incomplete; do not assume a successful return means every stored entry was read. v0.2.6 does not fix this, and no workaround has been verified.
- **[#773 — `to_tgraph` error-bar units](https://github.com/tatsuki-washimi/gwexpy/issues/773)**: Error-bar quantities with units incompatible with the series can be accepted through raw values without a compatibility check. The report describes a ROOT graph that may contain misleading uncertainties; this release review did not reproduce it. v0.2.6 does not fix this, and no workaround has been verified.
- **[#774 — invalid HDF5 `frequency_unit`](https://github.com/tatsuki-washimi/gwexpy/issues/774)**: A nonempty but invalid `frequency_unit` attribute can fall back to Hz without warning. The frequency axis may then be interpreted in the wrong unit. v0.2.6 does not fix this, and no workaround has been verified.
- **[#777 — `SeriesMatrix.to_hdf5` Quantity attributes](https://github.com/tatsuki-washimi/gwexpy/issues/777)**: Quantity-valued custom attributes can be omitted from HDF5 output without warning, causing metadata loss on round-trip. v0.2.6 does not fix this, and no workaround has been verified.
- **[#778 — `WhitenTransform.inverse_transform`](https://github.com/tatsuki-washimi/gwexpy/issues/778)**: The inverse transform is reported to return dimensionless data instead of restoring the original physical units; this release review did not reproduce the report. Downstream consumers may treat the result as physically unitful when it is not. v0.2.6 does not fix this, and no workaround has been verified.
